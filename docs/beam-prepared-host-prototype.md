# Host prepared BEAM publication prototype

Source-only candidate, unbuilt, revision3 seeded exactly published part245 ab336e4b1bae4152a6f183f0c99a08efbe025098. Baseline 6460 tests, 4843 source contracts, 159 diagnoses, six exclusions and 484 MFAs. No Erlang loading exports or magic-reference claims.

ModuleRegistry owns an opaque PreparedBeamImage. Preparation owns input bytes, decodes actual code and the first raw Attr/CInf ETF term, computes the native significant-chunk MD5 through the frozen shared checksum reader, and preflights every export's reachable implementation. On-load images, lambda tables and native record definitions remain explicit unsupported preparation forms. A generated module_info adapter is permitted only after verifying the exact decoded move/call_ext_only body including the actual module atom/import and arity; invocation then calls the real erlang:get_module_info import against the published native descriptor. Direct BeamModule API contracts remain unchanged.

Publication validates all live owned resources first under the existing registry gate, then duplicate and current-plus-old conditions before mutation. Duplicate and blocked module lists follow reverse input failure order. Successful publication updates every export and descriptor atomically using the registry's rollback transaction and consumes resources only after success. It neither creates nor retires purge states. Old-only state is allowed, retaining its existing image while creating a new current generation. Replacing current source-owned code retains source owners in its old snapshot; normal registry calls continue acquiring actual image leases and observing pending/retired code. Atom observation during parsing is intentionally outside rollback.

Public names describe a host facility rather than native erlang:prepare_loading/finish_loading. Unsupported body sets reject the entire prepared image; no subset is advertised as a loaded full module. Physical BEAM heap layout, native frame metadata and on-load staging/finalization remain partial. Captured local bytecode closures remain unsupported.

Shared source: BeamChecksumReader.cs, BeamChecksumWire.cs, BeamLambdaWire.cs and BeamLambdaDiagnostics.cs copied exactly from the frozen closure execution candidate, with no closure execution imported. Their native checksum ordering is backed by the independently retained six original file-only MD5 observations; this candidate still needs its own gates. Reuse actual .NET IncrementalHash and existing C# ExternalTermFormat/ModuleRegistry instead of introducing a production BEAM/OTP dependency. Source derivation and Apache-2.0 Erlang/OTP attribution remain consolidated in OTP-PORTS.md; no source license banners or private LICENSE.local.txt copied.
