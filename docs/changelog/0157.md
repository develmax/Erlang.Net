## Part 1774 — 2026-11-15 — Keep immediate arithmetic inputs in X0

**Part status** — Verified against the Windows release corpus.

### Changes

- Carry a computed arithmetic operand directly into a GC BIF in X0.
- Mark X0 live through the instruction and retain the proven integer type of inner arithmetic.
- Update the register and frame regression to the reference frame size.

### Decisions and compatibility

- Follow pinned OTP 29.1.1 beam_ssa normalize and beam_ssa_pre_codegen find_yregs. Reuse the existing typed register and compact operand writers. No dependency was added.
- The arithmetic instructions and Type payload of ex_slider now match. Register layout and other instructions in Code still differ.

### Validation

- All 1,366 Windows OTP 29.1.1 sources were accepted and emitted BEAM images. 399 files matched byte for byte, including ELDAPv3 generated from ASN.1 by C#. OTP accepted both images in all 967 differing pairs.
- Compared 394 changed images. 6 normalized instruction matches were gained and 0 were lost. Absolute Code-size differences changed by -10898 bytes in total.
- All 11 focused cases passed and the preceding compiler failed the new frame regression. The compiler block passed 3722 of 3830. The same 108 cases failed on part 1773. The original string Jaro case passed in this run.
- The full runtime suite and readiness regeneration remain pending.
