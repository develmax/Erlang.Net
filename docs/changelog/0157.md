# Changelog · Volume 0157

## Part 1774 — 2026-11-15 — Keep immediate arithmetic inputs in X0

**Part status** — Verified against the Windows release corpus.

### Changes

- Carry a computed arithmetic operand directly into a GC BIF in X0.
- Mark X0 live through the instruction and retain the proven integer type of inner arithmetic.
- Update the register and frame regression to the reference frame size.

### Decisions and compatibility

- Follow pinned OTP 29.1.1 beam_ssa normalize and beam_ssa_pre_codegen find_yregs. Reuse the existing typed register and compact operand writers. No dependency was added.
- The arithmetic instructions and Type payload of ex_slider now match. Register layout and other instructions in Code still differ.

### Validation

- All 1,366 Windows OTP 29.1.1 sources were accepted and emitted BEAM images. 399 files matched byte for byte, including ELDAPv3 generated from ASN.1 by C#. OTP accepted both images in all 967 differing pairs.
- Compared 394 changed images. 6 normalized instruction matches were gained and 0 were lost. Absolute Code-size differences changed by -10898 bytes in total.
- All 11 focused cases passed and the preceding compiler failed the new frame regression. The compiler block passed 3722 of 3830. The same 108 cases failed on part 1773. The original string Jaro case passed in this run.
- The full runtime suite and readiness regeneration remain pending.

### Handoff

- Schedule the last independent Y-to-X argument load ahead of the result spill when this lets the frame allocator reuse the released slot. In ex_slider:do_init/1 the stored fourth slider result currently overlaps the first slider until the first call to wxSizer:add/3. [Commands and evidence](../validation/part-1774/README.md).

## Part 1775 — 2026-11-15 — Reuse slots released by call argument loads

**Part status** — Verified against the Windows release corpus.

### Changes

- Move the independent argument load before the call result store.
- Require the existing linear allocation plan to show a smaller frame before accepting the reorder.
- Check the read and write of the same slot in the regression.

### Decisions and compatibility

- Reuse linear slot allocation and the existing late instruction rewriting pipeline. Compare with pinned OTP 29.1.1. No dependency was added.
- The ex_slider frame size matches. The slot layout and the instruction sequence still differ.

### Validation

- All 1,366 Windows OTP 29.1.1 sources were accepted and emitted BEAM images. 399 files matched byte for byte, including ELDAPv3 generated from ASN.1 by C#. OTP accepted both images in all 967 differing pairs.
- Compared 31 changed images. 1 normalized instruction matches were gained and 0 were lost. Absolute Code-size differences changed by -103 bytes in total.
- All 11 focused cases passed and the preceding compiler failed the new frame regression. The compiler block passed 3722 of 3830. The same 108 cases failed on part 1774.
- The full runtime suite and readiness regeneration remain pending.

### Handoff

- Implement repeated trims based on slot lifetime between calls. The part 1774 comparison found 869 modules with fewer trims than OTP, including 302 modules with straight-line functions missing a trim. [Commands and evidence](../validation/part-1775/README.md).
