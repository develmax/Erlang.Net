## Part211 - 2026-10-13 - Port signal queue pressure and lossless protocol close

**Part status:** completed local implementation/checkpoint;original comparison pending212;native OS options and full scheduling remain unfinished.
**Objective:** separate incoming signal pressure from output driver pressure and make language send suspension/decline real.

### Changes

PortOpenOptions/PortMessageParameters/RuntimePort add independent busy_limits_msgq positive/clamped/disabled limits and actual pending command payload bytes. RuntimePorts marks message pressure strictly above high (distinct from driver >=high),reduces bytes after real admission,and wakes below low. SendAsync waits existing driver/message pressure before admission;an accepted signal that triggers message pressure waits for relief without retrying or duplication. Close/owner death wake waiters;owned cancellation cancels sender waits. Async ErlangOperatorValues.TrySendAsync,Execution ! and registered send2/send3/send_nosuspend preserve return shape,aliases,priority,noConnect,invalid-option semantics. nosuspend now declines busy port sends without emitting bytes;send_nosuspend2/3 force the flag rather than ignoring it. Public synchronous C# host helper still enqueues directly and is explicitly outside async guest admission equivalence.

Protocol close also waits accepted writes before cleanup. Previously a sub-high-watermark write could be cancelled by a following close. New PortDrainHostChecks/Parameters starts an actual delayed reader,captures1MiB packet4 wire bytes to a unique temporary file,waits child OS exit,and verifies exact length/header/payload before cleanup. Probe drain-file and slow-echo modes are owned C# test executables. Separate namespace types/domain constants follow SDK style.

## Part213 - 2026-10-13 - Real child descriptors, shared stderr and custom argv0

**Part status:** completed Windows local implementation and validation; Linux execution and original comparison pending214. Native driver ABI/fd and full platform/resource compatibility remain partial.
**Objective:** implement the remaining spawn-port options through actual child OS resources rather than accepting settings without their effect.

### Changes

- PortOpenOptions parses in/out as accumulating direction flags, stderr_to_stdout, independent arg0, nouse_stdio and overlapped_io. It preserves stderr/stdio conflicts and rejects arg0 for shell spawn. Existing line, packet, busy-port and message-queue settings remain separate.
- PortChildProcess/ManagedPortChildProcess retain the SDK path for ordinary ports. WindowsPortChildProcess uses CreateProcessW with explicit inherited handle lists and separate executable/argv0, real overlapped parent pipes, shared child stdout/stderr handles and NUL for disabled child directions. Windows nouse_stdio keeps standard handles as the pinned driver does. WindowsPortCommandLine preserves arguments and resolves executable suffixes as the original search does for the selected PE executables.
- LinuxPortChildProcess uses GNU libc posix_spawn file actions, owned close-on-exec pipes, stdio0/1 or auxiliary3/4, a shared stderr descriptor and closure of unrelated child descriptors. LinuxPortPipeStream uses nonblocking parent IO and cancellation-aware asynchronous waits; owned waitpid observation reaps child exit. Explicit close releases port resources without pretending to kill arbitrary OS programs.
- RuntimePort/RuntimePorts consume the typed child transport, distinguish missing output descriptors (ebadf) and broken pipes (epipe), and preserve original input/output-only EOF/exit differences found in Unix and Windows source. The existing output/signal queues, monitors and lifecycle still operate on the real resources.
- Owned probe modes inspect true native argv0, emit ordered packets to stdout and stderr, test closed stdin, and use auxiliary descriptors. Twenty-five permanent source fixtures cover flags/order/duplicates, shared streams, custom/empty/spaced argv0, argv replacement, invalid settings, auxiliary IO, input EOF/output failure and output-only data suppression.

Pinned OTP-29.1.1/ad058237: erl_bif_port.c settings; Unix sys_drivers.c and Windows sys.c child setup, descriptors, executable lookup, IO/error and exit observation. Altered source attribution is consolidated in OTP-PORTS.md. System API declarations/documentation were consulted for Windows CreateProcessW/explicit handle inheritance, GNU libc spawn ABI and posix_spawn; no glibc implementation or binary is copied or packaged. Reuse SDK Task/Stream/SafeHandle; no new NuGet package/framework or production BEAM. Unsafe code only pins owned memory during nonblocking syscalls. See dependency-decisions.md for links and adaptation scope.

Backend scope is Windows and Linux64 GNU libc with the required spawn file-action extensions (closefrom requires glibc2.34+). Non-GNU/32-bit/macOS option transports, Windows batch/DOS launch formats, native registered driver/fd/stdio drivers, complete errno/GUI/physical scheduling/resource/distribution/upstream/performance contracts remain unfinished.
