## Part 1759 — 2026-11-15 — Reuse stack slots through map and binary instructions

**Part status** — Implemented and verified against the Windows release corpus.

### Changes

- Admit stack operands of map updates, map lookups, binary construction and tail extraction to the existing slot allocator.
- Treat alternating map destinations as writes on success. Preserve interference with live failure-edge values because map extraction can write before a later key fails.
- Add one normal-entry-point regression for all four fixture functions. The allocation in lookup drops from six slots to four, matching the pinned OTP allocation.

### Decisions and compatibility

- Follow OTP 29.1.1 beam_trim and beam_validator for operand positions, writes and failure semantics. Reuse the existing control-flow graph and BEAM operand rewriter. No dependency was added.
