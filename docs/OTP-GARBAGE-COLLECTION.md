# Process garbage collection prototype source and reuse audit

Pinned reference: OTP-29.1.1, ad05823719d77c8faee87348ea39513d4e2f99c5. Original checkout is unchanged. Source reads used git show against the pinned tag.

Source-directed behavior: erts/preloaded/src/erlang.erl garbage_collect/0,1,2 and get_gc_opts; erts/emulator/beam/bif.c erts_internal_garbage_collect_1; erts/emulator/beam/erl_process.c request_system_task/sched_sig_sys_task and system-task execution. No external package, actor framework or production BEAM dependency. Existing ProcessRuntime signal admission, cancellation, selective receive and termination fanout are retained. SDK System.GC is the available actual managed collector; it operates on the entire CLR managed heap, not an isolated BEAM process heap. Major forces blocking compacting maximum-generation collection; minor forces generation zero collection and is a hint, as the original type is. This proves actual collection and request-result behavior, not BEAM heap sizing, roots, reductions, max_heap_size enforcement, physical scheduler priorities or dirty system-task equivalence.

The original list parser overwrites duplicate async and type values in traversal order, delays type validation until dispatch, and marks malformed options with bad_option before target/type validation. Async IDs accept arbitrary terms and each request has identity even for repeated equal IDs. Synchronous remote collection uses a generated unique reference and selective reply receive. Queued requests execute at signal admission, including suspended processes; termination replies false exactly once for all pending requests. This managed scheduling model retains the existing runtime's host callback boundary: an arbitrary blocked host Task does not admit Erlang signals until runtime control or death.

Message-area audit: pinned git grep across erts finds garbage_collect_message_area only in preloaded erlang.erl and erlang.beam. bif.tab has no such BIF. The exported preloaded body calls erlang:nif_error(undefined), so the implementation raises error:undefined and does not claim or invent collection behavior.
