## Synchronous spawn: exact origin of 47/48

The failing spawn-opt-callback-payload source first asserts serial {0,1}, then calls seq_trace_print(hidden), then asserts {2,3}. The retained native result is badmatch {serial,{47,48}}. This follows the pinned implementation exactly; it is not evidence of hidden IO or extra tracer traffic.

The synchronous branch at 12987-12999 declares Uint serial, assigns SEQ_TRACE_T_SERIAL(token) directly, and assigns that tagged Eterm to the parent's raw clock and last-count without unsigned_val. The child reply has numeric serial 2, so its small Eterm is 47: erl_term.h:271 make_small is (value << _TAG_IMMED1_SIZE) + _TAG_IMMED1_SMALL; the size is 4 and tag is 0xF. Parent token remains the request token {0,1}, which explains why the earlier assertion succeeds. seq_trace_print_1 at erl_bif_trace.c:3229-3237 calls seq_trace_update_serial even with print flag false. erl_trace.c:920-942 increments raw clock47 to48 and constructs token lastcount47/current48. No print event is emitted with the flag false, but counters advance.

This branch applies to every local synchronous spawn using erl_create_process, including callback and MFA spawn_opt, spawn_link, spawn_monitor, and spawn where their wrappers reach that producer. The selected runtime currently converts the reply token serial to its numeric value before storing the parent's clock; that is the concrete mismatch. Matching the pinned observable behavior requires a domain-owned native tagged-small conversion for this branch only, with unsigned machine-word wrapping preserved. Asynchronous spawn_request does not use this implicit synchronous-parent update. A fixture correction from {2,3} to {47,48} keeps independent Expected {ok,done}; additional cases should assert the next send/print and explicit serial reset, rather than obscure the difference with a counter reset before testing it.
