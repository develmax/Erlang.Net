## Caller implementation review

- Expr.Call and Expr.Apply retain SourceLine. Parser builds line starts once, then binary-searches token offsets; the formulas produce 1-based lines for both exact starts and interior offsets. Calls/applications retain an already assigned nonzero line. LF and CRLF inputs use the same LF boundary model as ordinary source scanning. This does not reinterpret Erlang argument values or evaluation order.
- CodeGeneration carries SourceLine into regenerated expression trees and SourceFilePath into ModuleDefinition. GeneratedModuleCompiler's optional sourceFile override supplies the same source identity as the original fixture; its omitted argument keeps the existing default. No artificial filename rewriting occurs in the stack comparison.
- SourceCallLocations uses ConditionalWeakTable keyed by ModuleDefinition identity, with a per-module concurrent line cache of immutable Erlang terms. Cached values capture filename strings, not ProcessContext/runtime instances or delegates rooted back to the module. This avoids a permanent static module registry and dynamic process retention. Files/lines are cached separately from property/default atoms.
- Execution evaluates callee/arguments in the existing order, then scopes the current call location around actual Call/Apply dispatch. ProcessContext.EnterSourceLocation copies only the current immutable execution frame, uses the existing disposable restoration scope, and restores the prior AsyncLocal/visible frame on normal return, error and tail-call unwinding. It does not mutate a shared caller chain in place. The observed12 stacks substantiate tail/non-tail behavior for the new API path.
- RuntimeExceptionCapture.Call propagates caller SourceLocation only when an explicit sourceLocation was supplied for the API-owned first frame. Existing callers with the default null preserve prior native formatter/error-info and caller-Nil behavior. Depth bounds and captured-stack markers remain intact. ProplistValueLookup supplies cached proplists.erl:222 only for its function_clause path and still strips its own wrapper exactly once.

No remaining get_value-specific return, error, top-frame or supported caller-metadata mismatch was identified in the reviewed code/current evidence. A finite witness set alone is not the argument: the source partition is exhaustive across empty/nonempty/reached improper lists, equal/unequal atom and tuple keys, tuple arity0/1/2/>2, other property entries, and arbitrary defaults/values. Existing exact Term equality is the inherited key-comparison dependency.
