## Blocker 1: publication and retry are not yet a concrete algorithm

The text proposes a monotonic function-table version as a possibility but does not define its publication point or the atomic snapshot used by the registry's classification/handler selection. An initial factory snapshot followed by a separately locked IsModuleLoaded check is insufficient. A freshly published matching factory may be missed or an obsolete factory/current-state combination classified incorrectly. A stale check followed by public Call also loses the captured handler identity.

Existing lock order is concrete: RuntimeFunctionEntries.External(safe=true) holds its function-entry gate while Modules.HasExport acquires the registry gate. Consequently new registry→Functions lock acquisition is forbidden. The design cannot declare all gates unnested without considering this existing Functions→Registry path. User factories, handler bodies, source admission waits and awaited callbacks must run outside both gates.

A bounded design refinement can use a stable per-identity publication cell: snapshot immutable entry data plus its published identity/revision while holding Functions.gate, release it, then make current-code/purge/selected-handler decisions under Registry.gate while validating that cell through a lock-free read. Mutation must publish the changed payload/revision atomically after updating entry data under Functions.gate; no registry callback takes Functions.gate. If the observed publication changed, return Retry before acquiring a handler lease or invoking anything. If a lease has already been reserved, every retry must explicitly release it. Define the linearization point: module/purge state and selected handler are stable under Registry.gate, and the matching entry publication is validated there. A later concurrent registration may affect the next call; it must not retroactively change an already admitted invocation.

Per-key validation avoids unrelated factory registrations causing global retry starvation; immutable payload reference publication avoids unchecked version wrap/ABA. These are source-level options, not an approved algorithm. The revised design must select an actual mechanism, enumerate every write path (Register and unresolved placeholder admission included), describe memory publication/overflow if numeric versions are used, and show cancellation/fairness on retries. Deterministic barrier HOST controls must demonstrate registration between initial snapshot and registry decision, concurrent current-code replacement, and no user factory invocation under a held monitor. A guessed version counter with no validated final decision is not enough.

## Blocker 2: original restored Fun cannot pass through existing factories implicitly

The intended exact original Fun in undefined_lambda arguments and badfun is correct. However loaded.Factory(values).Invoke executes a newly constructed FunctionTerm. Both compiler producers close over that newly created result and pass result! into SourceFunctionInvocation:

- NamedFunctionReferences.Create builds a new FunctionTerm and its delegate calls SourceFunctionInvocation.Named(...,result!).
- Execution's Expr.Fun Create similarly binds SourceFunctionInvocation.Anonymous(...,result!).

Thus extending admission alone will hand the temporary created fun to the callback/error when a retained factory proves stale; it will not hand the original decoded wrapper. Replacing decoding-runtime module lookup does not fix this identity transfer. The executing runtime must supply BOTH the selected factory and the current module/handler authority. Creation and ETF Restore itself must never invoke a handler.

Before implementation, choose explicit per-invocation original-Fun threading through the factory/invocation protocol, including both producers and typed source admission. Preserve normal direct fun calls without an override. Do not use ambient mutable state or catch/replay body undef to substitute identity. This likely requires NamedFunctionReferences.cs and Execution.cs in addition to the proposed eight-path list, unless a concrete alternative demonstrates correct identity without those changes. The ceiling needs reapproval after the actual mechanism is specified. Prove ReferenceEquals(originalWrapper, callbackArg2) and ReferenceEquals(originalWrapper,badfun payload) on the retained stale-factory path, not merely equal serialized identity/environment. Reentrant handler retry must keep that original wrapper and not acquire a retired-image execution lease.

## Supported direction and explicit partial boundaries

FunctionTerm.Invoke already checks badarity before invoking any delegate; keep it. A still-active captured old source image must run before considering missing CURRENT. Pending purge waits use existing caller control pumping; abort rechecks and resumes valid code, successful retirement rechecks for current compatible code/current incompatible code/no current. A missing result owns no source lease and must not bind clauses or execute the old body. Never intercept undef deliberately raised inside an admitted body.

IsModuleLoaded already provides a locked loadedModules query including zero-export publications. Use it or a registry-internal equivalent in the SAME decision snapshot; Exports.Any is not a valid replacement. A CURRENT compatible module without a pre-registered matching local factory is still an acknowledged resolver gap: module registration does not eagerly install every compiler local fun factory. Equal fingerprint alone cannot justify arbitrary index/environment execution. Direct foreign captured-image ownership is separately partial; restoring a wrapper into another runtime does not prove arbitrary captured FunctionTerm transfer safe.

The first slice can truthfully cover decoded wrappers plus stale source-factory admission with pre-registered compatible factories, original-Fun identity and the above retry protocol. A fresh-compatible-module resolver and direct foreign captured image require independent approved scope. Reuse327 selected-handler provenance and direct no-fallback callback admission, but do not rely on the current full run being completed or published yet. Keep all raw-BEAM capability limits and missing undefined_lambda→undef behavior; no undefined_function recursion for an absent callback.

Verdict: native scope and functional direction accepted as preparatory design; **two blockers prevent code-ready approval**. Root requested no328 implementation at this point.
