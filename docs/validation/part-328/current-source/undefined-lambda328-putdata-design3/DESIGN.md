## 1. Stable per-key immutable publication

Use one stable LocalFunctionPublicationCell for each existing (Module,Index,Arity,Unique) key. Cells are installed in RuntimeFunctionEntries' dictionary under its existing gate and are NEVER replaced or removed. Each cell holds a reference to an immutable LocalFunctionPublication containing Identity, EnvironmentCount and the origin-aware factory (or null). There is no numeric revision or overflow; every mutation publishes a freshly allocated payload object, never reusing a prior payload reference (no ABA).

Writers are exhaustive: (a) first Restore/first invocation placeholder insertion creates an unpublished cell, initializes its nonnull immutable placeholder, then inserts under Functions.gate; (b) Register and new compiler RegisterSourceFactory update the cell under Functions.gate using a new complete payload, and Volatile.Write is the final publication after any bookkeeping updates. Existing Find/identity-provider reads use the same cell payload; no independently authoritative mutable Entry dictionary remains. Legacy public Register keeps its signature through an adapter into this common publisher. External function cache writes are a separate keyspace and unchanged; they cannot invalidate a local key snapshot. Subsequent placeholder acquisition for an existing key does not rewrite an existing payload.

Acquire a cell/payload snapshot under the EXECUTING runtime's Functions.gate, then RELEASE that gate. An immutable LocalFunctionInvocation contains the exact original restored wrapper, cell reference and captured publication reference. A cell exposes only a lock-free IsCurrent(snapshot) operation implemented by ReferenceEquals(Volatile.Read(ref current),snapshot). No registry code ever enters Functions.gate. This respects existing External(safe=true): Functions.gate → Registry.gate; the reverse ordering is prohibited.

Under Registry.gate, after resolving its own current/old/purge/module state and before reserving any lease or capturing a handler callback, compare the relevant cell publication by Volatile.Read. The successful comparison is the invocation decision's linearization point L. All module/purge/handler data was read while holding that same registry lock, so it is stable at L. Only this key's publication matters. A write after L affects the next invocation, not an already admitted invocation. A write before L changes the immutable object and forces Retry. No equality comparison of payload fields can hide a new publication.

For a no-factory branch: under Registry.gate compute CURRENT-code status including zero-export loadedModules, select the actual process undefined_lambda export/body and normal admission data, then validate cell at L BEFORE lease reservation. If changed, return Retry with no lease/user invocation. After successful L, retain existing327 callback admission phase and invoke outside gates; do not relookup through public Call. A currently present callback body raising undef is ordinary failure, not a second lookup.

For a matching factory branch: retrieve immutable factory/environment data from the snapshot and construct its temporary FunctionTerm outside every gate. Standard compiler factories only validate/copy environment and build delegates, never execute the closure body or call a handler. SourceFunctionInvocation then makes actual image/purge/lease admission under Registry.gate, validates the SAME invocation token at L, and only then reserves its normal lease. A publication changed during off-gate construction is therefore detected before closure code. The temporary constructed object can be discarded on Retry; the original restored Fun cannot be replaced.

Legacy HOST custom factories are still arbitrary delegates. Retain their existing API through an adapter, run a registry-gated publication preflight at L before invoking them outside gates, and do not claim their private delegate internals obey compiler-source admission. The genuine language path uses origin-aware compiler factories and the second admission validation. No user factory runs while either monitor is held. A factory with wrong environment count preserves the existing badfun path without invoking it; final module/selected-handler decision must still validate the same cell, not act on a stale snapshot.

## 2. Retry, pending purge and lifetime

Registry source admission returns an explicit Admitted / MissingCurrentLocalFunction / Retry discriminant. Retry and Missing own NO execution lease; missing is never encoded as null Image alone. Pending purge remains the existing owner mailbox WaitForControlCompletion followed by full loop/reclassification. Validate the publication after each settled wait and before selecting a lease or missing disposition. Abort may resume old code; retirement plus another CURRENT image means badfun; retirement plus no CURRENT permits direct undefined_lambda selection. Still-active old code runs before no-CURRENT fallback.

A source factory returns a FunctionTerm, so an admission Retry needs a precise channel through its unchanged Term-returning invocation ABI. Use a new internal LocalFunctionPublicationChangedException carrying the exact immutable LocalFunctionInvocation token. SourceFunctionInvocation throws this ONLY on the Retry admission result, before entering Execution or user clauses. The restored-wrapper loop catches only this type AND ReferenceEquals(failure.Invocation,itsCurrentInvocation). A nested fun's unrelated retry token must not be swallowed. This is internal control flow, like existing compiler tail-call signals: it is NOT an ErlangException and cannot be mistaken for a user undef. No wrapper exception escapes the owned restored invocation loop in the supported source path.

On retry, release all gates and abandon the temporary fun, charge await context.ReduceAsync(), then acquire a fresh executing-runtime snapshot. The existing reduction slice yields and admits signals; every iteration observes halt/cancellation and existing suspension policy. No new sleep/timer, global invalidation or arbitrary retry limit is needed. Repeated mutation of one key may delay it, but cannot starve unrelated keys or suppress process exit indefinitely. Do not await inside Functions/Registry gates. No lease is acquired before Retry; if an implementation ever moves a reservation earlier, it must dispose before retry and obtain new review.

## 2a. Mandatory interpreted/module-null second validation

Execution.Expr.Fun also registers factories when ModuleDefinition is null. These create real interpreted/erl_eval closures. SourceFunctionInvocation.Anonymous currently skips AdmitSourceFunction in that branch, so the source-image admission check alone is NOT sufficient: a relevant publication can change after the initial preflight and off-gate factory construction, before interpreted body entry.

The Anonymous module-null branch MUST perform a publication-only validation immediately before Execution.InvokeAnonymousAsync whenever an invocation token is present. Call a small method on ModuleRegistry.LocalFunctionDispatch that locks Registry.gate, validates the token's cell by the same lock-free Volatile reference comparison and returns success/Retry. It never acquires Functions.gate, reserves an image/lease, infers CURRENT code or selects an undefined_lambda handler. On Retry, throw the same invocation-token-specific internal control-flow exception; only its owning restored loop catches and charges ReduceAsync before a fresh snapshot. On success L is interpreted body admission. A publication after L affects a future invocation and does not cancel an already admitted body.

Direct interpreted fun calls with null invocation retain their existing path; genuine interpreted closures remain executable even without a ModuleDefinition/current-image identity. Do not reinterpret module-null as missing local code or attempt source-lambda loader behavior. Normal source Named/Anonymous retain their existing image/purge admission validation. This correction fits the SAME fourteen-path ceiling: SourceFunctionInvocation.cs and ModuleRegistry.LocalFunctionDispatch.cs are already owned, with no new Runtime/Terms type or production test hook.

Required deterministic control: create a genuine interpreted anonymous closure using existing evaluator path, serialize/restore through the executing runtime, pause after its factory snapshot/construction but before module-null body admission, publish a replacement for that same identity, then resume. Prove the old interpreted clause never runs, token Retry occurs without a lease, and the fresh publication's body runs once. Include unchanged direct interpreted invocation, unrelated-key mutation, cancellation/signal responsiveness during repeated relevant mutation, and no spurious undefined_lambda callback. Source inspection must enumerate BOTH nonnull and null Anonymous branches; a source-image-only test cannot cover this case.

## 3. Preserve the original restored Fun through BOTH compiler producers

Remove Restore's immediate Factory(values) shortcut. Restore only constructs the wrapper and immutable environment/identity bookkeeping; no handler or closure body executes. At Invoke the wrapper's own FunctionTerm.Invoke has already enforced badarity, then it acquires context.Runtime.Functions' cell/payload. Decoding runtime is not authoritative for factory, module, purge or handler selection.

Add internal RegisterSourceFactory(identity,arity,environmentCount,Func<IReadOnlyList<Term>,LocalFunctionInvocation?,FunctionTerm>) while retaining existing public Register unchanged via its legacy adapter. Both NamedFunctionReferences.Create and Execution's Expr.Fun Create gain an optional invocation parameter. Direct source creation passes null. Restored invocation passes its token. Each factory-created delegate calls SourceFunctionInvocation with originalFun = invocation?.OriginalFunction ?? result! AND the invocation token. This explicitly avoids the current temporary-result! trap in BOTH producers.

SourceFunctionInvocation.Named/Anonymous thread originalFun unchanged into every admission and missing callback. It is the badfun payload and argument2 to undefined_lambda, even though a temporary fun's delegate did the admission. The source expression/body environment still comes from the selected factory's validated immutable environment; no private FunctionTerm mutation or ambient override is allowed. Handler retry apply(originalFun,Args) re-enters the original wrapper with a NEW invocation token and fresh executing-runtime snapshot. An admitted body intentionally raising undef is never retried/intercepted.
