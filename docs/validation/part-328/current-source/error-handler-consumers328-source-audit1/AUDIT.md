## Supported next functional increment: undefined_lambda/3

Pinned `beam_common.c:1669–1728` and independent JIT `beam_jit_common.cpp:1307–1364` establish the exact decision:

1. Wrong arity is badarity before handler lookup, retaining the original fun and argument list.
2. A still-active old fun runs its defining code. Pending purge suspends/retries through the purger; it must not invoke the handler early.
3. When its local fun entry is unresolved, current code for the defining module means badfun(Fun), avoiding infinite handler recursion. A different newer image is not permission to run its arbitrary closure.
4. With no current code, call the process-selected handler's **undefined_lambda/3** with Module, the exact Fun and an ordered proper Args list, in the calling process. Missing callback yields undef. Its arbitrary returned term is the fun-call result; callback errors/throws/exits propagate through ordinary invocation rather than being converted into undef.

Default `error_handler.erl:117–126` attempts ensure_loaded and apply(Fun,Args), otherwise raises undef using the fun-shaped stack frame. This does not require implementing a complete code server in the first custom-handler slice. `fun_SUITE.erl:753–812` supplies the genuine load-race reference: a custom undefined_lambda retries the same fun via apply/2 while another process loads the module. `nofrag_SUITE.erl:130–162` proves a custom handler may simply return Args, with a deserialized unresolved fun retaining its environment. Do not execute or rewrite that historical hardcoded ETF as a claimed newly compiled image.

## Concrete current storage and smallest implementation seam

`FunctionTerm.Invoke` in Erlang.Terms already enforces arity first, preserves local identity/environment, and invokes a ValueTask body. It should remain a general term type, without a Runtime dependency or blanket catch of ErlangException.

`RuntimeFunctionEntries.Restore` creates a genuine unresolved local FunctionTerm for a decoded identity/environment. Its current body retries an available exact factory, otherwise throws badfun if a factory/current export exists and throws undef if absent. This is the smallest useful first route: dispatch a missing local-fun callback in the executing ProcessContext's runtime after releasing the entries gate. Avoid accidentally using only Restore's captured runtime when a fun executes in another context. Preserve exact fun identity/environment and recheck factory/image state coherently before selecting the missing route. `Modules.Exports.Any` is a weak proxy for current code: a loaded zero-export image also prevents native handler dispatch; use an explicit locked current-image/module query.

`ModuleRegistry.AdmitSourceFunction` similarly already selects matching fingerprint/owner, waits for pending purge through owner mailbox control pumping, acquires the execution lease before execution, and differentiates retired current-module badfun from absent-module undef. For captured source closures, add an explicit **admission result** for missing current code (or a narrowly typed internal signal), consumed in `SourceFunctionInvocation.Named/Anonymous`. Do not catch every undef from Execution.Invoke: a real closure body may itself raise undef, and must not be run again through the handler. Returning a handler result must bypass closure body/prelude completely. Resolve/recheck under the registry gate; call user handler only after leaving all runtime/registry gates and without retaining a retired image execution lease. Recheck state after pending-purge completion and before choosing the branch.

Expected runtime-only seams: a shared327 process-handler dispatcher plus RuntimeFunctionEntries and ModuleRegistry admission; compiler adaptation is SourceFunctionInvocation with a result/discriminant type if needed. Constants/diagnostics in semantic Names/Diagnostics files, one type per file. Reuse327 missing-handler recursion/fallback policy only after comparing it with native undefined_lambda lookup (which does not request recursive undefined_function for a missing callback). Preserve callback source lease/image/flow restoration across yield, cancellation and failure. No raw BEAM import/opcode allowlist widening, no scheduler heap rewrite, no native fixture/ABI changes.

## Minimum meaningful controls before release

- A real compiler-created local fun with free variables: capture/export ETF while its module is loaded, unload/purge it through actual code APIs, restore it through binary_to_term, install a custom handler and invoke. Handler observes same self/process dictionary, Module, exact Fun/env and ordered Args, and returns an observable marker. Bound actual compiler source/identity; do not fabricate private fields or a fake fun identity.
- Yield inside callback, then return; throw/error/exit from callback; missing handler module/function; handler replacement between calls; another process retains its own handler. Default missing code still undef with intended frame.
- Arity mismatch invokes no callback. A newer incompatible loaded image gives badfun without callback; identical-image relink runs real closure and preserves environment. A still-live old image executes its old body. Failed module load does not count as current code.
- Pending purge abort resumes real old body; successful retirement invokes missing-lambda only after settlement and only if no current image. Actual handler cancellation/kill must unwind without extra image leases. Add these on the established code-lifecycle HOST framework; do not broaden the first restored-fun slice into an unproved general raw-BEAM path.
- Genuine RED on published326 with the same legacy-compatible public helper: unresolved fun invocation gives undef instead of the custom handler marker. No missing reflection/import/type failure accepted as semantic RED.

Recommended sequence: finish327 dispatcher; implement restored unresolved local-fun callback plus real same-process/yield/error/arity/current-image controls; then extend captured source-closure admission with lifecycle/pending-purge controls. This delivers actual handler functionality. Unknown registered-name sends remain badarg. All original cases here are proposed, not executed.
