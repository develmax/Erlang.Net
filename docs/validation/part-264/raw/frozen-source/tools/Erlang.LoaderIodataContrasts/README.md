# Original gzip iodata loader contrasts

This standalone successor is source-only and unbuilt. It adds sixteen predeclared fresh-VM scenarios without editing the published default eleven-case exporter, declarations, wrapper or evaluation expressions. No SDK is referenced or executed.

Arguments: verified installed OTP root, repository root, new output directory, source-build evidence. The bounded process capture implementation is reused from the existing tool, with only its private namespace changed. Source commit/tag/log digest, installed OTP_VERSION and invoked OTP29/ERTS17.1/JIT/root gates remain. The wrapper is compiled with warnings as errors; genuine source/BEAM/disassembly and all argument/result/exception/full-stack streams and file hashes are retained. One immutable original constant BEAM input is checked by SHA.

All gzip payloads and decompression observations are produced by the installed original zlib. The actual erlang:prepare_loading wrapper is called independently after raw gunzip capture. Source-selected Code0 or decoded Beam equality is checked before assigning an original_code/decompressed_code label. Module-invalid observations validate complete rewritten [Module,SelectedCode] arguments and erl_erts_errors information after retaining the entire native stack. Static summary literals match the independently declared source hypotheses; no managed expected result is used.

Empty/truncated gzip must follow pinned zlib_nif inflateEnd EOS enforcement, rather than BCL GZipStream accepting partial streams. All sixteen hypotheses still require a fresh pinned original run before claiming compatibility. The existing eleven-case proof remains unchanged and does not cover this missing wrapper input domain.
