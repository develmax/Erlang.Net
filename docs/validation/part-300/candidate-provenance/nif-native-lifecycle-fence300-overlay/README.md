# Bounded native lifecycle fence

Source-only overlay against actual Main's Part 299 bounded native backend. The author did not build, run HOST/native/original checks, edit Main, or mutate Git. The manifest records the exact NifNativeLibraryOwner.cs parent SHA. Apply separately from the lifetime overlay and its public-purge timing revision.

Initialize and DisposeAsync now acquire one process-wide native lifecycle fence before their existing owner monitor. Initialization retains the fence across verified file open, native entry/load callbacks, entry validation and binding construction. Disposal retains it across unload callback, NativeLibrary.Free, verified-handle release and dependent callback/allocation teardown. Ordinary function Invoke still acquires only its owner monitor. No native callback is moved onto the registry/runtime monitor stack.

The gate deliberately serializes all bounded backend native initializations and disposals across runtimes, owners, aliases and copies. It does not infer physical library identity from a hash or path and makes no performance claim. This is a conservative equivalent exclusion boundary for the pinned OTP committed native unload/load window in erl_nif.c 2559-2617, not a claim of general resource/thread/dirty-work ownership support or exact scheduler behavior.

Acquisition is synchronous because these trusted initialization/unload callbacks and owner methods are synchronous. Initialization honors cancellation while waiting and checks it again inside its owner monitor before native callbacks; disposal uses an uncancellable acquisition so cleanup remains owned until actual completion. The scope allocation happens before acquiring the semaphore permit, avoiding an allocation-failure permit leak. All exits use lexical using cleanup. A thread-static diagnostic rejects same-thread nested lifecycle entry before blocking. It is neither inherited authority nor general native callback reentry support. The internal scope must remain synchronous on its entering thread, as both call sites do.

Lock order is lifecycle semaphore -> owner monitor. Invoke acquires only the owner monitor, never the semaphore. Failed initialization returns or throws and releases its fence before the existing initializer wrapper invokes owner disposal, so its cleanup does not recursively acquire a retained permit. The bounded callback allowlist cannot acquire module-write admission or another lifecycle operation; expanding that allowlist requires a new wait-for/reentry audit. Native teardown failure still attempts every existing teardown stage and releases the lifecycle fence afterward. Repeated owner disposal remains serialized and does not return before an earlier disposal leaves the fence.

The root should validate the unchanged managed/native trusted SDK contracts against the merged source. For additional concurrency proof, use an owned barrier to hold an actual native lifecycle operation, verify another owner/runtime cannot enter init/unload until it releases, then reverse the order. Cancellation and exception controls should demonstrate later independent entry remains possible. A reflection-controlled managed gate barrier is only controlled host concurrency evidence; actual native callback evidence must be reported separately. No new concurrency/native/original execution result is claimed by this artifact.

No Core registration, public load_nif API, additional callback ABI, per-hash identity mapping, generic BEAM load instruction or observable purge-timing change is introduced here.
