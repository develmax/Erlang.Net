# Conservative native init/unload exclusion proposal

This is a design proposal, not implemented or executed source. The pinned original `erl_nif.c:2559-2617` excludes native reloading across committed unload callbacks and dlclose by holding code-modification permission. Running those callbacks outside registry/runtime monitors is compatible with a separate process-wide native lifecycle fence.

Use a single process-wide, non-reentrant native lifecycle gate for this bounded backend. Acquire it before the existing per-owner gate in both `NifNativeLibraryOwner.Initialize` and `DisposeAsync`. Hold it across verification/open, nif_init, native load callback, validation/initial binding construction, and across unload callback plus NativeLibrary.Free and dependent callback/environment teardown. Always release it on failure. Normal function invocation retains only the per-owner gate and does not acquire the lifecycle gate. Failed-initialization cleanup acquires the gate only after Initialize has returned or thrown and released its acquisition.

This deliberately serializes distinct libraries as well as the same physical object. It avoids incorrect identity inference from equal content hashes, canonical path strings, symlinks, hardlinks, or separate copies. No OS file-identity abstraction or platform-specific inode/file-index lifetime is needed for this conservative first implementation. A later per-physical-file implementation would need identities from the same verified, retained OS handle used for loading, plus a proved lifetime-safe mapping; content hash alone is not that identity.

Lock order is lifecycle gate -> owner gate. No code may acquire the lifecycle gate while holding an owner gate. The caller must not hold registry/runtime monitors when entering native initialization or disposal. The existing initializer retains logical code-modification admission but executes outside those monitors. A retirement worker can wait for the lifecycle gate without holding code-modification permission. A new initializer can wait while retaining its ticket because the bounded unload callback ABI exposes no module writer or nested native loader. Any future callback expansion that can synchronously request code modification or another lifecycle operation requires a fresh wait-for/reentry audit.

The current native callback operations are synchronous, so a SemaphoreSlim or equivalent non-reentrant synchronous gate can be held without crossing an await. Initialization acquisition honors the caller cancellation token before touching owner state; disposal acquisition is not caller-cancellable, because cleanup must remain an owned obligation until actual completion. Cancellation never releases an acquisition while native code remains inside it. A thread-local diagnostic reentry guard should fail a same-thread nested acquisition before waiting; it grants no code-write authority. Do not use a reentrant Monitor alone to claim exclusion for nested init/unload callbacks.

Suggested bounded verification: hold actual unload at a controlled native/managed bridge barrier, start initialization on a second runtime and owner, verify it has not entered native init until unload and dlclose finish; reverse the order; repeat through distinct path aliases and separate same-hash file copies to prove conservative process-wide exclusion. Cancellation before gate acquisition must leave an owner available for cleanup. Initialization and unload exceptions must release the fence exactly once and permit a later independent operation. An in-flight ordinary function call must finish before the owner's unload and must not attempt the reverse lock order. Keep fake managed gate tests distinct from actual native callback evidence.

This fence does not implement native resources, dirty schedulers, native threads, upgrade, callbacks during whole-VM shutdown or the public load_nif BIF. No performance improvement is claimed.
