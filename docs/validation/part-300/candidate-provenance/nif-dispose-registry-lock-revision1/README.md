# Nonblocking owned native closure at Dispose entry

Source-only narrow overlay, no Main edit/build/native/Git. ProcessRuntime.DisposeAsync still performs the direct self-join guard before dispatch. It queues registry native closure in an independent Task.Run actor with both initialization and retirement diagnostic flows isolated, before entering DisposeRuntimeCoreAsync and its initializer completion join. The existing nativeShutdown Task remains joined at the original failure-preserving shutdown boundary. No fire-and-forget ownership is introduced.

This removes a new synchronous registry-monitor wait before DisposeAsync's first await. Historical InitializationLifecycleChecks.ShutdownPending holds that registry monitor in an initializer callback and releases it only after obtaining the disposal Task; the synchronous call therefore caused a deterministic wait cycle until its existing timeout. The original test must remain unchanged. Root should run that historical group, NifLifetimeHostChecks and native ownership before the full suite.

Registry nifClosing and its admission/commit checks remain protected by its existing monitor. Queuing the close does not itself linearize admission refusal on the disposal caller thread: an admission that wins the registry monitor first can initialize before closure, and its actual owner/reservation is still captured and drained by CloseNifLifetimeAsync. Disposal completion still requires actual closure, all reservations and cleanup. No separate uncoordinated closing bit/gate is introduced. Immediate same-thread registry admission refusal before returning a disposal Task is not promised by this correction.

No duplicate new HOST mirrors the historical regression: existing ShutdownPending supplies the owned initializer barrier, caller-side release and queued-work cancellation assertions. Existing native lifetime checks provide admission/commit drain and cleanup-failure coverage. Their previous successes do not establish this correction until rerun.
