# NIF runtime integration audit 2

Source-only audit. No Main edit, registration, compiler/build, native dispatch or network. The adjacent source-bindings.json records exact source hashes, line anchors and pinned excerpts; pinned blobs are saved unchanged. The seven-callback trusted Windows fixture is an internal development prerequisite. Its success cannot establish generic load_nif/2 or ABI2.18 completeness.

## Rejected pending-badarg divergence

**Rejected:** a NIF could call enif_make_badarg, ignore its return, then successfully return a normal term on original OTP. Pinned erl_nif.c1791–1800 sets exception_thrown and process error reason; interpreter emu/bif_instrs.tab525–527 and JIT beam_jit_common.cpp650–652 both unconditionally replace the returned value with THE_NON_VALUE when that flag is set. The auxiliary native invocation path also does so (erl_nif.c5456–5459 and5482–5485). Prototype unconditional guest-pending throw after return therefore matches this dimension; do not change it to test only result==0.

Separate, genuinely incomplete contracts: enif_is_exception checks flag AND sentinel (erl_nif.c1288–1290); enif_has_pending_exception returns the latest pending reason (1803–1807); repeated raise_exception overwrites process fvalue (1796–1800). Prototype NifCallEnvironment.Fail uses first-exception-wins and conflates guest errors and host callback violations. That broader behavior is not exercised by this fixture, whose badarg branches return immediately. Before adding arbitrary raise/badarg APIs, model guest reason/class separately from host failures and expose proper pending queries. A managed ABI failure must never unwind through native code or become a fabricated guest badarg.

## Admission and publication, exactly what OTP does

Dynamic load_nif BIF deliberately returns bad_lib before filename conversion (erl_nif.c4618–4626). Direct calls are load_nif instructions (emu/ops.tab854–864) and know their actual instruction/caller image. Direct filename conversion precedes old-image checks (4730–4763). Do not infer caller from a saved MFA string; do not treat every syntactic apply expression as dynamic, because compiler optimization can lower static apply to a direct call. A real M/F-parameterized dynamic apply must remain rejected independently of malformed filename.

Current image, old image and pending on_load image are distinct. Old caller returns old_code; a pending on_load image selects that pending instance and the appropriate previous instance (4758–4771). Same image already loaded rejects reload (4774–4776, reload disallowed since OTP20). A previous generation with a NIF invokes upgrade rather than initial load; missing upgrade errors; upgrade veto restores old private-data pointer (4956–4977). Initial load veto reports load error and installs no functions (4980–4986). Do not use process/module-name aliases to conflate those instances.

ABI version, VM variant and module identity validation precede function validation (4799–4826). Every function must exist and be nifable; duplicate entries and unsupported dirty flags fail (4853–4875,4896–4900). Crucially check_is_nifable is `!are_nifs || are_nifs[index]` (4700–4704): **absence** of a -nifs declaration preserves legacy eligibility, while a **present** declaration restricts eligibility. Do not make the attribute mandatory universally or treat absent and explicitly empty as the same. Declaration validation needs pinned compiler/loader tests beyond the seven fixture observations.

Native interpreter i_load_nif holds code-modification permission across erts_load_nif and releases it afterward (emu/bif_instrs.tab640–645). C# reservation must therefore coordinate competing module replacement/purge/publication across the callback, without holding a monitor lock across native work. A final generation recheck alone is insufficient to reproduce native serialization: it would allow replacement to commit while initialization is in progress. Use a runtime-owned asynchronous code-modification admission/ticket respected by every relevant writer; avoid reentrant callback deadlock.

All NIF entry points and resource callbacks become callable atomically only after successful callback admission (4990–5009;5042–5048). Error rollback erases staged entries, rolls back opened resource types and closes handle (5020–5033). External OS/native side effects cannot be undone by a managed Dictionary rollback alone.

## Current runtime anchors and concrete gaps

- ModuleCodeImage is immutable identity only (ModuleCodeImage.cs3–8). ModuleCodeDescriptor has functions/exports/fingerprint/sourceOwner but no NIF declaration or binding state. ModuleInformationSnapshot currently hardcodes nifs=[] (line29); original nifs_in_module enumerates installed native functions, not merely declarations (erl_bif_info.c5772 onward). Keep declaration eligibility distinct from installed inventory and invalidate cached module information on successful attach.
- ModuleRegistry owns a gate, current/old image dictionaries and source-owner identity. AcquireSourceCode/AdmitSourceFunction and ProcessContext activeCode leases already guard executable image lifetime. Source Execution.InvokeAsync41–55 attaches the exact ModuleDefinition owner/image, and InvokeFrame105 onward resolves clauses. A native override must be checked before fallback clause selection and at every actual function-entry route, including local/tail calls and closures. Replacing only the external MFA dictionary would leave local calls/funs executing fallback bodies.
- BEAM ExecuteLocal and its local-call loop switch function/pc internally (BeamRegisterInterpreter.cs26 onward,192–201); that bypasses source Execution. Compiled BEAM entry and local/tail/fun dispatch need the same image-bound override admission. BeamLinkedCode has no NIF declaration/instruction support. Do not route only call_ext and call that integration complete.
- Source -nifs and -on_load remain reserved/unsupported parser attributes (AttributeControlNames9–10, Parser158–167). Prepared BEAM on_load is separately real: ticket owns a distinct CodeImage, callback enters owner=ticket, FinishPendingOnLoad revalidates captured current/old descriptor/bodies then publishes that same image (OnLoad130–182). An on_load NIF reservation must bind ticket image and migrate unchanged on commit; failure/retirement closes that generation outside the registry gate. Current-only prototype Acquire would reject pending image.
- DeleteModule moves current image into oldCode rather than retiring it (ModuleRegistry374–408). A native library must survive that move and old closures/local invocations. FinishPurge marks image retired only after existing purge worker kills/waits for old actors (ProcessRuntime963–1014); coordinate native in-flight leases/dirty/resource references before unloading. Cancellation can abort purge, so its rollback must not prematurely retire live native state.
- ModuleRegistry.Apply snapshots many dictionaries but not future NIF reservations/leases or external native side effects (519–570). Extend explicit transaction state; never hide native initialization inside configure() while holding gate.
- Standalone NifGenerationLeaseTable is not registry atomic admission: it locks its own gate then queries registry current image; image replacement can occur after that check, before Initialize/publication. Adding registry->NIF lock acquisition would invert the existing NIF->registry order. Integrate a single registry reservation state and capture/revalidate generation; native initializer/load/unload execute outside locks. Do not expose internal methods solely to simplify a harness.

## Implementation order that makes the real target more true

1. Add actual declaration metadata and validation to source/module descriptors and BEAM preparation, preserving absent versus present-empty; keep original fallback function bodies and immutable image identity. No public registration yet.
2. Add registry-owned image attachment transaction: Reserved -> Initializing -> Ready/Failed and Retired. Capture exact caller/source owner or pending ticket, descriptor generation and old state under gate. Acquire code-modification admission respected by replacement/purge as well as competing loads, release monitor gate for native work, then revalidate and atomically install all overrides. Revalidate cancellation/retirement after callback; failed publication owns cleanup. Preserve native callback error ordering rather than invented CLR errors.
3. Implement a common image-bound function-entry hook after source/BEAM lease admission and before fallback body. All external, local, tail, captured fun and BEAM routes consult the same immutable Ready binding snapshot; old/current images stay independent. The load operation itself must retain its caller image while outside locks.
4. Connect delete/purge/pending-on_load commit and rejection, runtime halt/dispose to native lifetime. Retire forbids new invocation, waits in-flight callbacks/resources as applicable, unloads once outside all runtime/registry gates and frees OS handle after unload. Unwound task is not interchangeable with dirty job/resource quiescence. Avoid Task.Run fire-and-forget unloading without runtime ownership and join.
5. Build caller-aware direct source/BEAM load instruction plus independent dynamic BIF route and exact filename/error contracts. Add genuine callable export only when real supported platform loader/admission/overrides work. Do not add always-error skeleton or guest notsup substitution to improve presence count.
6. Generalize native ABI separately: all required callbacks with exact type/signature, terms/env/resources/exceptions/dirty/concurrent lifetimes; platform loaders and Linux global exported shim. Retain trusted fixture allowlist until then. Expand independent native fixtures per capability, not by mutating the existing hash-bound C fixture unnoticed.

## Generic ABI blockers, not fixture defects

Windows nif_init copies all180 function pointers plus2 trailing fields from the supplied table (erl_nif.h343–352,385–388). Prototype fills seven slots and leaves173 null. Arbitrary initialization itself can invoke any slot before it returns; Windows DLL imports do not reveal all indirect callback use. Entry minor2.18 is a fixture-version validation, not a host feature-negotiation promise. Do not expose this table as a generic2.18 loader or fill unknown signatures with one throwing function pointer.

Linux libraries use exported enif symbols; the main JIT assembly does not supply them. A typed export shim/global loader namespace and lifecycle registration are actual prerequisites. Variadic/resource/binary callbacks, dirty jobs, native-created threads, OS errors and upgrade/takeover are still absent. NIFNativeAllocationOwner's fallback reclamation is diagnostic containment for the fixed fixture; it must not silently masquerade as original cleanup after arbitrary load-veto leaks. Native code is not sandboxed by trusted-hash checks.

## Independent contracts before public completion

- Direct current-image load success and before/after fallback, malformed filename, OS missing/init/version/variant/module mismatch; true dynamic M/F apply with malformed and valid filename returns the explicit bad_lib branch. Preserve full original errors separately from portable projections.
- Absent -nifs, present empty, valid subset, missing function, duplicate entry, illegal dirty flags. Installed module_info(nifs) changes only after publication and reflects current generation.
- NIF ignores make_badarg return then returns a valid term: original still raises badarg (rejected-hypothesis positive regression). Two raise_exception reasons verify latest pending reason; has_pending/is_exception check both sentinel and valid-term inputs. Host failure and guest reason are distinct tests.
- Barrier-controlled two simultaneous loaders; replacement/purge during initializer; cancellation after native load succeeds but before commit; no partial override visibility. Keep old bodies usable on veto and zero leaked reservations/OS handles.
- External/local/tail/local fun/external fun/BEAM entry all select same correct generation; replacing current retains old fun native code until actual purge. Reload same image errors, new-image upgrade missing/veto/success follows original old private-data handling.
- Real prepared BEAM on_load load success then keep transfers exact binding; rejection/callback death/changed generation retires pending binding and leaves published image unchanged.
- Native active-call versus purge/halt/dispose barriers; unload exactly once after quiescence, no native callback under registry/runtime gate, no dangling pointers. Test nested/reentrant callback behavior and error-return/throw cleanup independently.

These are implementation and proof obligations. None of the proposed new contracts or runtime integration has executed in this audit. The existing fixed seven-callback fixture remains a valid bounded prerequisite; no pending-badarg bug in its current behavior is claimed.
