## New coherent increment

ModuleCodeImage no longer eagerly allocates the dormant binding table and gate. An internal ConditionalWeakTable creates an attachment on first use; unused images have no attachment entry or extra per-image fields. Concurrent lookups return the same published identity. GetValue may run losing factories under contention; there is no claim that only one temporary object can be constructed. HOST source checks absence before first use and identity across 64 concurrent readers.

The registry now owns lazily created code-modification permission. Asynchronous tickets retain its semaphore across awaited native initialization without retaining a registry monitor or flowing ownership through AsyncLocal. Native initialization must happen while holding the ticket, outside ticket.Run and all registry/runtime monitors. Only synchronous capture/commit mutations run inside ticket.Run. A ticket serializes explicit mutations, cannot be reused after disposal, and defers a reentrant Dispose from inside its mutation until that mutation actually exits.

Existing synchronous host writer APIs enter thread-bound nested scopes before their registry monitor. ThreadStatic scope authority exists only for the synchronous mutation stack and never follows spawned tasks or async continuations. Scopes must close on the owning thread in reverse order; waiting for admission while already holding the registry monitor fails immediately instead of inventing an unsafe reverse lock order. Acquiring a new async ticket from inside a synchronous owned mutation is also rejected. Synchronous scopes are not awaitable and must never cross await.

Seventeen concrete writer entry points participate, listed in writer-hook-ledger.json: registration/source/intrinsic writes, module identity/descriptor/deletion, Apply/preload transactions, loader-reference/image/on_load finishing, prepared BEAM publication, pending staging/commit and purge prepare/finish. Private RetirePending inherits its FinishPendingOnLoad admission. Metadata reads and on_load callback status/outcome updates keep using their existing monitors; they do not replace executable images and do not wait for code permission. Native initialization is not implemented here.

Guest delete_module, finish_loading, load_module and finish_after_on_load await code permission with mailbox control processing and cancellation before entering synchronous mutations. Abandoned async acquisition is canceled and any already acquired ticket is disposed before rethrow, so process cancellation cannot leak admission. Purge prepares through guest-aware admission, and finish/rollback reacquires noncancelable ownership to settle its existing pending state. LoadPreparedOnLoadAsync stages and finishes through async permission, releasing it before running its Erlang callback. Existing synchronous host entry points may block for permission, while normal registered guest writers use asynchronous admission.

The candidate includes source-only HOST contracts for lazy identity, blocked writer versus continuing registry reads, nested Apply registration, canceled admission and subsequent reacquisition, a killed guest delete while waiting, child-task authority isolation, disposing an active ticket mutation, scope-order and reverse-monitor-order refusal, and transaction rollback. The previous image table lifetime/barrier contracts remain. No new public BIF registration or NIF dispatch hook is enabled.
