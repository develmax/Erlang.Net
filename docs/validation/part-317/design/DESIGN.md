# Finish memory/0,1 with a measured CLR payload profile

Design only; no implementation or Main change. Next candidate should ship BOTH public functions after the storage hooks below, rather than end at another private diagnostic. The native contract measures dynamically allocated emulator memory, not OS residency. Exact ERTS object headers/carriers or JIT physical-byte identity are not prerequisites for a truthful CLR adaptation.

## One explicit accounting scope

Use a documented **CLR SDK-observed payload profile v1**, host-wide across the SDK ProcessRuntime instances and shared Terms pools in this CLR process. Atom storage already has that global scope today. Do not mix global atom/binary pools with an unexplained per-runtime total. Weak-key runtime registration lets a query sample each actual runtime's process-slot/mailbox storage and joined native payload domain once; it must not keep retired runtimes/images/processes alive. A query from either runtime sees that same defined host-wide scope. This is not the whole embedding application's managed heap, all native allocations, or resident/committed memory.

Count actual array/string payload capacities and native backing REQUEST extents, with an explicit exclusion of CLR object headers, collection hash bookkeeping, arbitrary Term object bodies, process-context/dictionary object overhead, JIT/loaded assembly native storage, OS port implementation memory and instrumentation bookkeeping. These omissions are declared scope, not zeros assigned to unknown physical sizes. `total` means the sum of this profile's measured storage, not an estimate of those exclusions.

| Public key | Genuine source and classification |
| --- | --- |
| processes | Allocated reference cells in actual process-slot backing arrays plus inline Mailbox.Entry payloads in actually owned queue nodes. Processes used is occupied slot-cell payload plus occupied mailbox-entry payload; unused retained slot-array capacity stays in processes only. |
| processes_used | The used value from those SAME per-source captures. No per-actor CLR allocation guesses or arbitrary share of GC heap. |
| atom / atom_used | Unique GC-observed atom-name string identities, UTF16 character payload `string.Length*sizeof(char)`. Observe/registration retains canonical names today; track Atom.Name's duplicate string identities too because Register returns its input. Immutable string content has no spare payload capacity, so allocated=used is genuine for this component. |
| binary | Unique live tracked byte[] backing capacity at BitString allocate/take sites. ByteView/shares count the same backing once; a constructor's copied buffer is a distinct real allocation. |
| code | Actual code-owned raw prepared-BEAM byte buffers, function/export/native-record/declared-NIF metadata arrays and prepared-body reference arrays. Element payload uses actual array length and Unsafe.SizeOf<T>(), not source length, module count, IL/JIT estimates or guessed object headers. |
| ets | Sum of SDK-owned ETS storage sources. Current source has no ETS table implementation or registered ETS API/storage factory: the initial source set is genuinely empty, hence zero. NativeBuiltinCatalog's ETS declarations are metadata, not allocated tables. Document absence of ETS functionality; do not claim implemented ETS from this zero. Any future SDK ETS factory must join the accounting source set before enabling its profile. Hosted/custom modules called ets are outside this SDK implementation scope. |
| system | atom + binary + code + ets + current backing-request extents from joined NIF payload domains across sampled runtimes. A NIF domain is counted once; it is not binary or process storage. |
| total | processes + system, calculated from the captured components. Never GC.GetTotalMemory minus a made-up process fraction. |

`binary`, `code` and atom-name strings are GC-observed: losing the last SDK wrapper does not promise an immediate decrease before collection, and a host-retained shared backing may remain alive. The identity registry uses weak keys with value-only category/size metadata, never a strong key/owner/runtime/image reference. Query enumeration may briefly root the current backing while measuring it. That is a truthful CLR retention adaptation, not native deterministic free. Native payloads follow their existing actual Free/Reclaim ownership boundary. No forced GC is part of memory/0,1.

## Small concrete storage changes

1. Terms: add one internal weak backing-identity registry and value/category types. Register the actual byte[] in BOTH BitString constructors/FromOwnedBytes path; ByteView observes the same key. Register atom-name strings at Observe/registration, including input identity retained by Atom.Name. Size is stored once from the immutable backing, with no hashing of buffer contents or recursive term walk. Canonical registry insertion stays under its existing gate. Shared byte storage is counted once even if later observed as code and binary: a single category bitmask chooses binary over code for that identity, never sums both. String/array references contained in code arrays are their own actual array cells; do not count pointed-to string/binary payloads a second time.
2. ProcessSlotTable: replace the sparse `Dictionary<int,Pid>` slot storage with a private growable `List<Pid?>` (or equivalent actual owned reference array). This gives real capacity and occupied cells without reflecting into Dictionary internals or guessing Entry headers. Preserve released-slot reuse, SortedSet scan windows/cursor semantics and identity lookup. RequireCapacity uses live identities, not the list prefix length; Remove clears a cell. Read reports under the existing runtime gate. Do not allocate a full ProcessLimit array eagerly.
3. Mailbox: add an internal capture under its existing gate: messages.Count times Unsafe.SizeOf<Entry>(), with allocated=used for currently owned queue nodes. This reads the REAL inline record payload; it does not price arbitrary Term graphs or assume LinkedListNode CLR headers. No per-message tracking allocation is needed.
4. Code: register arrays at the real ModuleCodeDescriptor allocation/init sites, the owned PrepareBeam input copy, and PreparedBeamImage Bodies array creation. The descriptor already makes independent arrays; register the backing array before wrapping it read-only, never a ToArray copy made just for measurement. Current/old/prepared/host-held code storage stays observable by weak backing lifetime without retaining code images or taking publication/purge leases. Fingerprint/attribute BitStrings stay in binary, not code twice.
5. Runtime: a small weak runtime source set; one partial capture helper copies current process/mailbox sources under their normal gates and awaits existing cancellable CaptureNativeAllocationsAsync for each real domain. Do not construct a missing domain. No domain→owner lock, global stop-the-world gate, detached waiter or code publication lock during an await. Read global backing identity samples once per call, combine the actual source values, then release all temporary references before formatting output.

This is bounded bookkeeping around existing real storage, not a general profiler/provider framework. New code should be roughly: storage registry/value/category in Terms; ClrMemorySnapshot/Names/query + weak sources/runtime partial in Runtime; small hooks in BitString/AtomNameRegistry, ProcessSlotTable/Mailbox, ModuleCodeDescriptor/ModuleRegistry.PreparedBeam/PreparedBeamImage, Core registrations, and essential tests. Existing native C/ABI/profile and actual allocation-owner algorithms stay unchanged.

## Available .NET metrics do not supply the partition

The installed .NET10 reference XML confirms GC.GetTotalMemory reports managed heap size excluding fragmentation; GetGCMemoryInfo HeapSizeBytes/FragmentedBytes describe the last collection, and GetTotalAllocatedBytes/GetAllocatedBytesForCurrentThread are cumulative allocation counters. They are useful separate diagnostics, but have no process/atom/binary/code/ETS attribution, exclude native allocations in the cumulative counter, and do not identify SDK-owned storage inside an embedding host. Do not use differences between those observations to invent the nine categories or force a GC to make them add up. The proposed profile instead adds real captured payloads and keeps any GC metric separately labeled. Sources: local Microsoft.NETCore.App.Ref10.0.11 System.Runtime.xml members GC.GetTotalMemory, GC.GetTotalAllocatedBytes, GC.GetAllocatedBytesForCurrentThread and GCMemoryInfo.HeapSizeBytes/FragmentedBytes; no metric was executed here.

## API behavior and capability

Default fresh SDK host uses the fully installed v1 hooks and has positive supported snapshots, including real process cells and atom/code payload; it must not return always-notsup. Read one `ClrMemorySnapshot` per call. memory/0 emits exactly total,processes,processes_used,system,atom,atom_used,binary,code,ets. memory/1 atom selects one integer; a list preserves order and duplicate equality from THAT record; [] returns []. Wrong outer type is badarg before capture. On a supported snapshot, an invalid head is badarg, while valid heads followed by an improper nonlist tail reach function_clause. maximum has no supported value on the uninstrumented profile and is badarg.

If a genuinely incomplete/disabled tracking profile is admitted later, capability acquisition must fail with notsup before atom/list name validation (including []). Never substitute unknown source values with zero, silently truncate a scan, clamp total against GC heap, or declare a partially installed tracker complete. The initial implementation should have the hooks installed from first relevant allocation in the fresh host; no pretend backfill of objects created by an older uninstrumented assembly. No artificial disable switch is needed just to manufacture a negative test.

Pinned erlang.erl12980–12982 explicitly says amounts are NOT gathered atomically. Individual storage sources must return internally valid values, and the combined record must satisfy its own partition arithmetic. Independent sources may reflect nearby instants; no STW/global epoch barrier is needed. atom_used<=atom, processes_used<=processes and total=processes+system are guaranteed by the profile's actual capacity/used definitions and one computed record, not numeric equality with BEAM.
