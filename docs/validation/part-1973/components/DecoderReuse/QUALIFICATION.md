# Reuse decoded instructions within one compiler dispatch

The source-only change reuses the most recent successful late-projection decode for the same instruction storage range and decoder limits. A compiler dispatch starts with a fresh BeamModuleCompiler. Compile-result caching and corpus configuration are outside this change.

## Aliasing audit

- The source snapshot is the Part 1971 focused-retake compiler shadow recorded in source-receipt.json. It binds all 39 direct source files and every changed file to SHA-256 digests. The isolated preimage accepted the patch with strict Git whitespace and long-path handling. The patch uses the same instruction reader and byte rewrites as the preimage.
- CodeGeneration makes a fresh BeamModuleCompiler before calling Emit. Emit calls its synchronous EmitCode callback once. The initial instruction buffer or projection buffer is fully written before the late analysis. Successive passes receive ReadOnlyMemory. A no-edit path retains its existing range and an edit writes bytes to a new buffer. Compiler source searches for writable memory recovery found no MemoryMarshal, Unsafe, ArraySegment or TryGetArray route through the late bodies. The other code-buffer aliases are early source/assembly initialization and separate local output. For example ColdBooleanCaseFailures changes the buffer of its newly populated remap stream and returns a new result. RebuildLineTable and the type-order pass also write fresh streams.
- The cache key compares the original memory by ReadOnlyMemory.Equals, which compares storage identity, offset and length. It also compares version, highest opcode, label count, function count, atom count and literal count. This includes the decoder's exact validation context. Any changed range or bound misses, including an identical clone. Eviction happens before attempting a changed decode and invalid data follows the existing null path. The last entry is explicitly released before WriteCode.
- BeamInstructionReader returns read-only instruction and per-instruction operand collections. The elements are immutable records containing offsets, immutable opcode definitions and immutable operand data. The stack-position list is populated only by the decoder callback, then exposed through its own read-only wrapper and IReadOnlyList parameter types. CallFrameTrims owns an independent list that it intentionally clears and repopulates, and is absent from the patch. Other standalone producers still own their own lists.
- Three callers used List.BinarySearch by byte offset. They now use one read-only lower-bound helper. The cursor advances between recorded operand starts, giving strictly increasing offsets, including typed Y operands. Thus the old exact match or complemented insertion point and the new lower bound select the same first record. Their subsequent loops are unchanged.

The performance trade-off is heap lifetime. One old decoded body can remain rooted until the next late-reader miss or the end of the dispatch. The scoped experiment should record peak working set as well as wall time. Any future in-place write to one of the input ranges would invalidate the identity proof and must either allocate a replacement or explicitly evict the cache.

## Reproducible A/B gate

The eight paths in benchmark-modules.txt were bound to actual Part 1970 full-uncached shard reports, generated bytes for Different rows, raw pinned bytes for Equal rows, and timing report hashes. The five Different paths cover expensive storage, syntax-domain dispatch, socket state machines, generated Megaco protocol code and ASN.1 compiler code. The three Equal controls cover wx, ASN.1 and small stdlib. Their archived times total 58.52 s per arm and 3.90 min for four arms. That is a scheduling estimate from jobs=1 shard timings taken under five-worker host load. The four actual interleaved runs measure the improvement. The longest parser modules exceed the short budget individually or in combination and are better suited to the later full check.

1. Build A from the same qualified source closure and B with only this patch, using the same build configuration, corpus tool source and runtime. Keep build and execution output directories isolated. Record closure, SDK/runtime, input source, transitive includes/macros, build profiles and pinned BEAM identities. Capture the same complete mandatory validation if the change enters a package.
2. Invoke run-ab.ps1 with explicit absolute paths to the same dotnet host and OTP inputs and the separate A/B corpus DLLs. Provide the same ASN.1 header directory and pinned OTP source directory to all arms. The script runs A/B/B/A with one job and process-local SDK guards, isolated TEMP and generated paths, and writes module, setup and comparison timings. Each arm recompiles every selected source. Corpus exit 0 requires all Equal. Exit 1 requires at least one Different and a complete report limited to Equal/Different. The runner validates fresh generated images and timing coverage before continuing. It records exit code, full process wall time and the maximum observed OS peak-working-set counter sampled around every 100 ms. The memory figure is for the corpus process, excludes children, and can miss a peak between the final sample and process exit. Raw stdout and stderr are copied without transcoding. Run in one quiet host window.
3. Run compare-ab.py with the run directory and pinned OTP installation. It checks that all four reports cover exactly the requested modules and that all per-module statuses, source identity, offsets and diagnostic entries agree. It compares the resulting raw bytes across arms. For each Equal result the tool already compared freshly compiled bytes to the original and omitted the duplicate. The checker hashes pinned bytes and reads every Different image directly. It reports both role means and per-arm values for setup and comparison, plus per-module comparisons, full arm wall time and the arm peak working sets.
4. Accept the optimization only if bytes stay unchanged and the effect survives the order reversal. Look separately at the two pairs and per-module variants. If effects or host load are inconsistent, keep the raw measurements and use another quiet interleave rather than claiming a speedup. For attribution, separately instrument both branches of the late reader with per-dispatch lookups, actual decodes, successful hits, reader CPU/allocated bytes and process peak working set. Keep that timing probe out of normal A/B and production source. Cache misses caused by a transformed byte range must remain visible.

The verifier passed its positive and negative self-check against copies of archived images. The PowerShell runner parsed successfully. This draft has no SDK execution, candidate byte result or measured speedup.
