The authenticated d97 CI passed all 9,432 unit cases and both Linux jobs, but failed the ordinary counters610 comparison. A genuine MFA child received a detached native reference without an executable owner; `counters:add/3` raised `badarg`. Private-owned execution passed. This was a runtime defect, not a comparison-parser or cleanup failure.

## Implementation

An actual retained, same-runtime process input can activate internal owned execution for its genuine compiler/prepared MFA child. Activation verifies the real process owner and execution turn, cancellation and termination, then enrolls the context under the same gate as VM shutdown before allocating frames. Public runtime options remain unchanged. Rootless ordinary MFA execution retains its allocation-free path. Fresh opaque callback activation is outside this correction.

The existing guest ownership pipeline now follows this context capability through registers, invocations, native and function boundaries, tracing and retirement. Process-dictionary migration imports into a destination frame outside the dictionary lock, rechecks the snapshot and commits atomically; losing or failed attempts dispose their frame. VM shutdown joins enrolled contexts even when the global owned profile is disabled.

NIF environments retain the actual caller mode. Independent environments keep their independent mode. Copying an independent result into an ordinary caller exports all relevant built-in native families with rollback of newly acquired Host carriers if aggregate publication fails. The original unique one-argument copy method remains available for existing callers and reflection checks. Native reference validity checks were not weakened.
