# Remaining Part 1979 frame lifetimes

The two retakes use the final Part 1979 release images and the unchanged frozen compiler identified in `README.md`. The reflections only run existing planning methods over decoded frozen instructions and transient in-memory operand substitutions.

## Terminal tuple carrier

The Sudoku function needs Y6 as the carrier of `get_coords/3` on its checked path and for the `badmatch` value. The successful final tuple projection can alias its destination Y0 with the retiring carrier. The same physical Y6 is redefined by `integer_to_list/1` later, when projected Y0 is still live. That later call result is defined at instruction 901 and used once at instruction 910. There is no intervening redefinition or incoming edge. Any of Y2, Y3, Y4 or Y5 is untouched from the string definition through frame release. The untouched target never changes exceptional access because the branch to `badmatch` precedes the suffix and the function has no handler. The old atomic planner already finds a safe compacted width of 9 after rewriting just those two operands. The frozen reflection with ordinary allocator settings records the four substitutions in `sudoku-redefinition-strict.jsonl`.

The source-only patch extends the final nested entry admission to an explicit checked arity. It attempts a definition split only after the old resolver declines and publishes it only when the old atomic proof provides a smaller frame. It requires one owned frame, a terminal edge-free suffix, no handler or trim, a call result with one outgoing read, and an untouched replacement slot. No call, line, failure or GC operands are moved or relaxed. The two regression bodies differ by an extra live use of the prospective spare slot. Patch hashes and exact preimages are in `sudoku-terminal-slot-strict.json`.

## Nested record call operands

The TLS function saves socket X2 into Y1 solely because forming the third send argument overwrites X2. The input state X0 has already been saved by the time that third argument is formed. Moving the socket into outgoing X0 immediately before the pure tuple projection preserves both old X0 and the second argument, independently of the rooted handshake record. Y1 is then written only once more to carry the first `update_record` result and read as a value replacement by the consecutive second `update_record`. X0 can supply this direct value, since the second operation consumes its inputs before writing X0 and the existing heap check precedes both updates. The post-call `badrecord` test and its frame remain intact. The exact frozen body transformation removes all four Y1 operands and the existing branch allocator returns 2 with original slot mapping `[1,-1,0]`. See `tls-send-slots-retake.log`.

The TLS patch plans a separate final rewrite for a single owned frame, one fixed-arity call and exactly four uses of the scratch slot with the proven input/output roles. The copy schedule and next record value are rewritten together with existing dead-frame-slot compaction. The focused raw structural regression includes a control with an extra observed value in the prospective slot. Exact strict replay and patch identities are in `tls-record-slot-strict.json`.
