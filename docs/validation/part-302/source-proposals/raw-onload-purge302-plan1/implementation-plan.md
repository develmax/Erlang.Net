# Raw failed-on_load purge prerequisite: reviewed design proposal

Plan only; no implementation or execution. Exact original reference is OTP 29.1.1 commit `ad05823719d77c8faee87348ea39513d4e2f99c5`, captured through read-only `git show commit:path`. Source bindings and exact excerpt hashes are in source-bindings.json. Current SDK source hashes are an audit snapshot and must be rebased onto the root's completed Part 300 source before implementation.

## Original protocol and contracts

1. `erlang:finish_after_on_load(Module, Keep)/2` is the raw code-loader primitive. The pinned BIF checks the Keep boolean, requires an actual pending on_load instance, and seizes code-load admission. With false, it clears deferred export references only (beam_bif_load.c 819-940). It does not move, purge, unload or forget the pending code. Repeated false remains possible before pending purge; a later true is not inherently rejected. The current SDK tests already preserve those return-value observations.
2. `erts_code_purger:finish_after_on_load/2` is a distinct preloaded-module request/reply wrapper, not the raw BIF. The purger first calls the raw primitive. For false, it then calls `erts_internal:purge_module(Module, prepare_on_load)`, checks processes in hard mode, and calls `complete` (erts_code_purger.erl 154-182). True performs no purge. Reply is sent after this protocol, without waiting for a native unload callback to finish.
3. `erts_internal:purge_module/2` is a privileged primitive with operations prepare, prepare_on_load, abort and complete. Its caller check is process identity against the VM-owned purger, not a registered name or caller-supplied atom (beam_bif_load.c 2088-2095). Unauthorized calls raise error:notsup before module/op validation. Authorized non-atom modules, unknown operations, overlapping prepare or mismatched completion are badarg paths. prepare returns false for absent/no-old code. prepare_on_load on an existing module assumes an actual on_load instance; this is a trusted internal precondition, not an advertised safe badarg case for arbitrary callers. Do not invent a friendlier public contract from the C assertion/dereference.
4. prepare_on_load saves the previous old instance, moves the exact pending instance into the old slot, removes the pending-instance pointer, then establishes pending-purge markers on that target's fun entries (2128-2166). Current code remains current. Process checks therefore target the pending image, not whichever old image previously occupied the slot. Saved previous old code must not be killed or retired by this purge.
5. Native stage admission remains held across process checks if fun-purge markers exist, preventing code staging from invalidating them (2112-2117, 2150-2157, 2169-2184). If there are no fun entries, stage admission may be released. This is separate from the short code-modification admission used at completion.
6. Hard checks kill processes that actually refer to the target and wait for their termination. Completion requires the matching prepared module. It calls erts_unload_nif on the target, removes target code, restores saved previous old code and finalizes/resumes suspended fun users (2222-2326). Abort is the ordinary soft-purge protocol and restores fun addresses in stages; the pinned failed-on_load wrapper always completes hard purge. Do not assume arbitrary abort-after-prepare_on_load is a supported wrapper route.
7. erts_unload_nif schedules actual native closure asynchronously. The owned Part 300 retirement ledger must queue the exact target and retain failure/shutdown joins; an unload failure must not become a new error or a wait in the public purge/wrapper response. Custom high-level LoadPreparedOnLoadAsync discard remains a separate host API that may join cleanup.

## Additional raw false -> true gap requiring an oracle first

The current SDK false branch is a total no-op. The pinned false branch clears deferred export addresses. On subsequent true, the pinned fixup installs only still-deferred addresses; otherwise it activates error-handler trampolines (887-898). Existing SDK Admission checks false,false,true results but does not check exports or body calls afterward. A new original observation must establish function_exported, module_loaded, get_module_info(exports) and direct call/error behavior for false -> true. Do not silently make false a full discard, or assume republishing every body is correct. A private per-pending-ticket export-finalization state can model the measured result without altering the public BeamOnLoadPhase enum, but its exact effect must follow that observation.

## Recommended bounded implementation sequence

First implement an internal, runtime-owned purge target/session engine and managed HOSTs, without registering a new globally callable erts_internal BIF or claiming a complete erts_code_purger service. The current runtime has an ephemeral worker plus codePurger semaphore, not the original persistent VM-owned purger process. Reusing that serialized worker with a non-forgeable, runtime-created request capability is sufficient for the internal engine; a registered name or AsyncLocal marker is not caller authority. A later public privileged MFA needs an actual owned purger identity/service and its own exact caller/refusal checks. Default inventory must stay unchanged during this prerequisite increment.

The session should capture the exact registry/runtime/worker, module, target pending ticket/image/descriptor/bodies, saved old snapshot and unique prepare identity. Capture and transitions happen under registry gate and existing code-modification admission, but no callback or cross-process await does. One active session per runtime is serialized by the existing purger admission. It owns strong references until metadata completion and has an explicit terminal result; a late/stale/foreign completion cannot remove a newer pending image.

Prefer the original move-and-save model for the old slot, rather than a shallow module-name lookup or a second independent generic purge. Construct a snapshot for the same pending image and stable prepared owner, save the complete previous old snapshot, remove matching loaderPendingImages/pendingBeamImages entries atomically, establish pending purge state on that same image, then expose the target as old for process-code checks. Do not clone/recreate ModuleCodeImage or native bindings. Keep a session fallback for SourceImage/source-owner lookup into saved old code while it is temporarily displaced; source funs and existing old execution must retain their exact original leases. Current exports/descriptors/inventory remain untouched.

Extract the existing code-reference scan/kill/unwind logic to operate on the captured target/session. Match both module and exact image when checking and completing. Preserve cooperative mailbox admission in waits; an uninterruptible body must unwind before purge can finish, rather than being deemed gone on a kill request. The failed fixture discovered during Part 300 demonstrated why a fake infinite Task.Delay cannot substitute for a control-aware process wait.

At completion, require the same prepared session/target, remove only that target old slot, mark its purge state retired, restore the saved old snapshot exactly, complete pending fun admissions, and queue the existing owned NIF retirement. Clear pending loader maps only for the captured ticket. Public metadata/reference completion does not await that retirement. Existing saved old/current image owners must remain owned, callable where appropriate, and unaffected.

Caller cancellation should cancel only the requester's wait; an admitted purger request remains runtime-owned, as a message to the original purger does. Runtime halt/disposal must join or consistently settle the owned session and keep both target and saved old images reachable until terminal handling. Do not interpret a cancelled host waiter as raw native abort or prematurely release image leases. A recovery path for whole-runtime shutdown must be explicit and must not be exposed as an invented OTP operation.

## Stage/fun admission is a separate correctness gate within this work

The current SDK has per-image pending-purge admission but no separate code-stage permission held across process scanning. Simply holding the existing global code-modification ticket across every await is unsafe: managed victim unwind/cleanup may itself need code-write admission. Before enabling target sessions containing callable funs, add a dedicated stage/fun fence or prove an equivalent admission policy. It must cover source and BEAM publication/relink routes, release/signal in every terminal path, and await outside registry/runtime gates. A conservative fence can block more staging than OTP, but must not change unrelated public error values or create code-writer/cleanup cycles. This needs review before implementation, not a claim that per-image lease checks alone reproduce the pinned fun-entry protocol.

## Verification matrix and native/original needs

- Fresh failed pending image: raw false alone retains pending identity; full owned protocol removes it, metadata settles before held cleanup, and restaging is possible only after session terminal handling.
- Existing current plus failed pending: current body/exports/nifs remain current; only failed pending native owner retires.
- Existing deleted old plus failed pending: save and restore the exact old image/descriptor/source owners; saved old process/fun is not killed, relinked or unloaded by pending purge.
- A process and captured source/BEAM fun referring to the pending image: pending call admission blocks correctly; hard purge checks/kill/unwind target that image; retired fun cannot enter it afterward. Check lambda and generated-source routes separately.
- Stale/foreign prepare completion, overlapping prepare, no pending image and malformed operation: distinguish internal host refusal from actual original privileged BIF contract. Unauthorized user process must never gain authority by registering the purger name.
- Requester cancellation, worker halt, callback cleanup fault and queued native unload failure: no stranded stage ticket, pending fun waiter, session or native obligation; preserve original error plus distinct cleanup errors. Public purge must not wait on or surface unload failure.
- Raw false -> true export/body visibility: original-only predeclared typed observations first, then SDK comparison. Keep this separate from normal failed-on_load purger wrapper behavior.

The existing pinned nif_SUITE t_on_load source (541-672) confirms original use of old/deleted generations, explicit soft purge and a separate receive of unload notification. Its nif_mod.c unload callback (310-316) emits an unloaded message. Reusing those original test helpers for a development-only oracle is preferable to pretending the current two-function trusted SDK fixture implements arbitrary observer callbacks. Do not expand the bounded native capability profile silently.

Original protocol observations should run in fresh source-built pinned VMs with raw ETF/stdout/stderr/process receipts and exact source/header/build hashes. A development-only unload notification/barrier fixture may establish callback order if needed; it is not admitted by the current trusted SDK profile. Managed fake-owner barriers can verify SDK queue/reference ownership and public completion timing; actual current trusted native counter checks can verify its real unload occurs once and fence exclusion is retained. Resource retention, dirty NIFs, upgrade and thread/on_halt callbacks remain outside this increment. No new observation or native compatibility result is claimed by this plan.
