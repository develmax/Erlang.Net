# Raw on_load visibility original observation proposal

Source only. No Main edit, Git mutation, compilation, native or original emulator execution, workflow dispatch or observed semantic result by the author. Draft artifact number is not a published part number. This is a standalone pure-Erlang original oracle; no SDK production algorithm, C fixture, NIF capability profile or default MFA changes.

Promote the source closure to tools/Erlang.RawOnLoadVisibilityObservations/original with byte-preserving attributes from gitattributes-proposal.txt. Source-plan.json hashes every executable collector/fixture/control/policy input. Its approved hash must replace the explicit workflow placeholder after promotion and independent byte verification. Do not normalize or adapt reviewed original fixture bytes after sealing. The workflow proposal builds exactly OTP 29.1.1 commit ad05823719d77c8faee87348ea39513d4e2f99c5, records real emulator/compiler build provenance and workflow head/run identity, executes owned process-capture controls, then collects nine fresh VM observations. It deliberately has no SDK execution or semantic-pass step.

The old and new fixture use the same module identity but distinguishable body values. Only new has on_load. Both are compiled once per source-built oracle into separate directories; neither directory is added to the VM code path. This prevents a failed external call from automatically loading a fixture file and contaminating the raw loader state. Only the observer's directory is on the path.

Nine cases cross fresh/current/deleted-old baselines with direct raw true, raw false,false,true and the normal erts_code_purger failed-on_load wrapper false. The wrapper cases actually return not_ok from the callback. The observer uses raw prepare_loading/finish_loading and a direct literal call_on_load_function site. Callback execution happens in its own worker and stores the local pending fun in that worker's dictionary. Existing old local funs are held by a separate worker. The observer never receives those live funs before the purge; it asks the workers for captured outcomes and monitors their termination. Actual exception reasons/stacks, including an expired fun inside a reason, remain complete raw terms. No PIDs, fun identity or errors are normalized away.

Each case records before-stage, staged, after-callback and every finalization-event snapshot: module_loaded, check_old_code, function_exported for both explicit exports, raw get_module_info(exports), remote body call, pending local-fun call and saved-old local-fun call. The expected-policy.json file predeclares certain source-derived typed expectations separately from the investigative false->true export hypothesis and exact captured-fun failure/order questions. Unexpected evidence must be retained and the hypothesis reported as contradicted; collection completion is not semantic conformance or SDK compatibility.

The binary process capture execute function is copied verbatim from the previously reviewed pending/varargs collector; capture-origin.json records its original source hash and exact LF function-text hash. Controls exercise non-UTF8 stdout/stderr with exit 3 and a parent that exits while an owned process-group child retains its pipes. Only that launched process group is killed on timeout, followed by bounded reap. Control success is synthetic capture evidence, not original emulator evidence. Every compilation/original VM retains raw stdout/stderr, argv, exit/timeout/pipe/reap receipt. Collector failure writes a distinct failure receipt and cannot produce a complete receipt.

After actual collection, independently verify the receipt's complete file set/byte lengths/hashes, copied source-plan and policy, original source-build/runtime metadata, nine ordered distinct fresh VM identities and raw process completion. Then apply a typed original-only guard. Any ETF decoder used for that review must support raw fun terms if a failed captured-fun reason contains one; do not drop the reason or substitute printed text to fit a limited decoder. Full snapshot and stack ordering remain available. Only after that review should the SDK raw false export behavior or missing purge session be changed.

This fixture does not establish native unload timing, resources, dirty work, same-library lifecycle fences, full privileged purger authority or general load_nif support. Those require their own evidence. Building/installing OTP is performed only by the proposed manually dispatched workflow; the collector itself never downloads or installs a runtime.
