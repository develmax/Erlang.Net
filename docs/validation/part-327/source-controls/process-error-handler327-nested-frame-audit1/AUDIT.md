# 327 nested custom handler frame ordering: source hypothesis

No managed/original execution. Bound baseline is published326 b51f050c287f3b91346e1d3e30e86061708fb035 and design4. This identifies a new-handler wrapper risk, not an observed SDK/original failure.

Current `CoreModules.cs:287–292` registers error/1 by throwing a new ErlangException(reason), with a non-explicit empty trace. `ErlangException.WithStackFrame:14–22` returns explicit traces unchanged; otherwise it constructs `Cons(newFrame, oldTrace)`. Compiler `Execution.cs:789` / `RuntimeCallFrames.Capture` prepends the called MFA on unwind, except apply/3 with a preexisting trace. Ordinary execution context frames are separate: `EnterFunction` records an innermost-first AsyncLocal chain, and `CaptureErrorStack` walks that chain outward. `ErlangErrorRegistrations` error/2,3 uses this capture and sets ExplicitStackTrace=true, so it is NOT a valid substitute for exercising error/1 non-explicit central wrapping.

If design4 wraps each selected callback error with WithStackFrame, then inner handler first creates [InnerHandler, error/1, ...], and outer wrapper next creates [OuterHandler, InnerHandler, error/1, ...]. This reverses the handler invocation ordering. A nested call is legitimate; no recursion suppression or equal-MFA deduplication is appropriate. The old generic compiler behavior already prepends outer remote-call frames on unwind; keep that wider existing limitation separate from the newly introduced selected-handler policy.

Pinned OTP `beam_common.c:1205–1308` returns explicit raised traces unchanged; otherwise it builds saved continuation frames and prepends the current function, placing the exception site/innermost activation before older callers. `call_error_handler:1310–1361` redirects the missing MFA into the selected handler with Module/Function/Args. `bif.c:1436–1440` error/1 raises the reason; error/2 at1449 onwards additionally supplies arguments. Normal stack frames may carry integer arity, not the entire argument list. Do not assert native error/1 retains both recursive callbacks' full three arguments. Tail-call elimination can remove callers; keep the outer nested call non-tail.
