The next useful bounded runtime option is process_flag(error_handler, Module) together with actual custom undefined_function/3 dispatch. This is a functional process option whose result can be observed through existing real source-module execution; it needs no invented BEAM heap, physical scheduler, or off-heap storage emulation. Current CoreModules accepts trap_exit, save_calls, node-monitor controls and async_dist, but rejects error_handler. ProcessContext.ErrorHandler is an immutable default atom; process_info exposes it. ModuleRegistry.Call throws undef immediately for a missing registered MFA. External function entries and compiled remote/tail calls eventually use that same registry route. Merely accepting the flag and echoing it in process_info would leave its real function unused and should not be presented as this increment.

The pinned bif.c2045-2051 accepts any atom without checking whether a module/export exists, returns the prior handler, and rejects non-atoms before mutation. erl_process.h2416-2447 stores process-specific handler data with error_handler as the default; the setter returns the prior value. beam_common.c1294-1342 looks up the selected module's actual exported handler function at arity3; when absent it raises the ORIGINAL undef instead of recursively resolving a missing handler. For undefined_function the callback receives original Module, Function and the full evaluated argument list, in the original process. The default Erlang handler has autoload and '$handle_undefined_function'/2 behavior. Undefined lambda and debugger breakpoint handling are distinct native paths. The pinned docs also mention undefined registered processes; that wider behavior needs its own source/caller inventory and must not be inferred from this direct missing-MFA branch.

Recommended proposal after Root review: add real mutable per-process handler state using existing ProcessInfoLogicalNames.ErrorHandler/DefaultErrorHandler constants; one separate registration helper for process_flag/2; a private Runtime helper validating a live self and changing the atom under the existing runtime gate; and one internal registry fallback for missing MFA using the selected actual registered undefined_function/3. Reuse the existing registry invocation machinery for handler source ownership, leases, tracing, async failure and source-tail transfer; do not invoke a raw delegate as a shortcut. No new public API or MFA registration is needed. A first ceiling is three existing production files (CoreModules, ProcessContext, ModuleRegistry) and two separate new helper/partial files; exact route factoring must be reviewed before committing that ceiling. The process_info getter already projects the actual field and needs no new default-catalog key.

Lock/recursion constraints: never acquire the Runtime gate while holding the registry gate merely to fetch the selected handler. Snapshot it before registry lookup, or use an atomic immutable-Atom field read consistent with the gated setter. Capture the actual handler export through the same normal registry dispatch and release every monitor before executing/awaiting it. A missing handler export must use a direct no-fallback lookup for this resolution; do not add a global recursion depth guard, because a custom handler may legitimately call another missing function or change its own flag. Preserve original undef behavior when no handler export is available and preserve unrelated badarg/badfun/native instruction admission boundaries. HasExport/function_exported and safe external-fun decoding remain pure presence/admission checks; they must never invoke a handler or autoload. A local nonexistent function that the compiler rejects before the registry is a separate boundary; no broad rewrite of all undef exceptions is proposed.

Meaningful ordinary cases can use one actual fixture module exporting run/0 and undefined_function/3, install its own module atom, then call an absent literal external MFA. Assert exact M/F/arguments and callback self, process dictionary side effect and scalar result; repeat through apply/3 and an external fun forced through an exported dynamic helper to avoid SSA literal folding. Add return/previous-value/reset/non-atom-no-mutation/unknown-handler-atom accepted/default child-noninheritance tests. Missing handler must raise undef without recursive overflow; existing successful calls and function_exported false must not invoke the callback. Add handler-raised throw/error/exit controls and one async HOST barrier proving original context, source owner/image/lease and eventual cleanup across an awaited callback. Verify same new required handler contract on historical326 production after a clean target build; valid option rejection is a genuine old-route RED, while missing type/selector/timeout is not. Existing public process_info, source-fun, purge-stage, apply/stack and sequence-trace regressions are required controls.

No new original collector is required for these first registered-source contracts: append new names to the existing ordinary CompiledModuleCases corpus and preserve all old names/source hashes. Actual original comparison remains pending until its normal published workflow executes. The ABI/native probes stay unchanged. Default kernel autoload/code-server behavior, undefined_lambda/3, debugger breakpoint handling, undefined registered-process interception and arbitrary genuine BEAM unknown-import admission remain explicitly unported by the narrow proposal. Rejected shortcut candidates for this next small increment: accepting spawn priority without changing actual scheduling; accepting message_queue_data without changing actual storage; and accepting min/max heap/full-sweep values without real managed resource behavior. RuntimeActorDispatcher currently uses one ConcurrentExclusiveSchedulerPair/TaskFactory and ProcessContext.SchedulingPriority is a fixed normal atom, so a priority flag alone would be a weaker next step. The recommended custom-handler route performs actual useful work on an existing execution path and keeps that physical boundary honest.

Revision2 independent-review refinements (no implementation):

Combined with erl_process.h2423-2425 returning error_handler for an absent process-specific slot, this establishes the new child's default handler even when the parent's handler differs. Handler admission must be atomic with code identity/lease capture. Do not perform HasExport(handler,undefined_function,3) followed by a separate normal Call: concurrent unload/replacement/purge could select a different handler or enter fallback recursion. Resolve the selected handler with fallback disabled for this lookup only inside the same registry admission/dispatch operation that captures its body, actual source owner/image and normal code lease. Release the registry gate before executing or awaiting it. Missing selection raises the original missing-MFA undef. Once a handler is actually invoked, its own legitimate nested public missing-MFA calls still use normal handler resolution; no ambient global recursion suppression or callback replay is permitted. Apply the same existing source-entry admission/flow restoration semantics as ordinary calls rather than inventing a special source-lease bypass.

Revision3 forwarded-failure frame contract (independent review prerequisite):

RuntimeCallFrames.Capture currently prepends every requested MFA except erlang:apply/3 when a trace Cons is already present. ErlangApplyDispatch.InvokeTarget also inserts the requested target if a non-explicit exception arrives with an empty trace. ErlangException.WithStackFrame prepends and clones unless ExplicitStackTrace is true. These three actual source files are now hash-bound. Simply selecting a custom handler inside ModuleRegistry.Call and returning its task would therefore allow its error to acquire a fictitious original missing-target frame at a compiler/runtime boundary. The previous three-existing-production-file ceiling is insufficient to guarantee this contract by itself.

Required distinctions before implementation:

1. When the selected handler export is absent, the lookup must raise original undef with the original requested MFA/fully evaluated arguments, preserving the existing caller capture/stack behavior. It must not recurse into another handler lookup or manufacture a selected-handler frame.
2. When an actual selected handler executes and raises, its real callback/callee frames and legitimate caller context must remain. Only the synthetic wrapper for the unresolved original target is excluded. This applies independently to literal/non-tail and tail calls, dynamic apply/3 and exported-helper external-fun invocation. An error from inside a successfully resolved real function that happens to be undef is not a trigger for fallback.
3. A selected handler may itself call a second missing MFA. That nested selection is legitimate and must remain enabled. Exact selection provenance must be scoped to the specific unresolved call boundary and exception/continuation, not an ambient global depth switch. A missing callback lookup disables fallback for that lookup only; once a callback runs there is no global recursion suppression.
4. Existing erlang:raise/3 ExplicitStackTrace behavior, including an explicit empty Nil trace and a supplied custom frame list, must remain byte/term exact. Do not set ExplicitStackTrace=true on ordinary callback errors merely to stop one frame insertion; that would suppress legitimate outer caller frames. Do not globally change WithStackFrame semantics or clear traces.

The bounded source ceiling must allow a narrow Compiler.RuntimeCallFrames adjustment and the Runtime.ErlangApplyDispatch boundary, plus separate semantic/provenance helper files if necessary, alongside the earlier registry/flag/context work. Terms.ErlangException is an inspected dependency and preferably stays unchanged; if any candidate needs a per-exception provenance change there, Root must approve the exact additional delta before authoring it. Any forwarded-resolution marker/contract must identify and settle the exact original missing-MFA boundary while preserving cloning/propagation and concurrent distinct calls. A global catch-any-undef fallback, a blanket explicit-stack flag, or an unbounded ambient suppression variable is outside the approved design. This audit specifies the required behavior, not an already implemented marker mechanism; a concrete helper algorithm and final path ceiling require Root review before implementation.

Revision4 concrete per-invocation algorithm for independent review BEFORE implementation:

Preserve the public Registry.Call signature. Add an internal shared CallWithDispatch(..., out ModuleCallDispatchKind dispatch) for existing Compiler friend and Runtime apply code. Initialize dispatch to Direct before halt/argument observation/lookup; set UndefinedFunctionHandler only after the actual selected handler export/body and its normal source image/lease are atomically admitted under the SAME registry gate, and before any synchronous callback invocation. The public Call wrapper ignores the out value. Each compiler/apply call owns a local dispatch variable; that value remains valid both if the synchronous invocation throws and if an awaited ValueTask later fails. No exception annotations, ConditionalWeakTable, AsyncLocal, global recursion depth, global suppression or Terms.ErlangException change is proposed.

Selection is one pass: snapshot the atomic per-process Atom handler without acquiring Runtime gate under Registry gate; look up the original MFA; if absent, directly look up Handler:undefined_function/3 once with fallback disabled for this lookup only. Construct its arguments from original Module/Function atoms and the already evaluated argument Terms. Capture the actual selected signature's body/source image/code lease through the same normal registry path. If absent, leave dispatch Direct and raise the original undef so existing requested-MFA capture remains. If present, set policy UndefinedFunctionHandler, release the registry gate and invoke through shared normal dispatch (SavedCalls/process trace/source flow, halt boundaries and lease cleanup preserved). A handler's own subsequent public registry calls begin fresh normal resolution, so nested legitimate missing calls remain enabled. Do not implement HasExport followed by a separate Call or catch-any-undef/badarg recovery.

One real handler invocation boundary captures callback failure centrally. After atomic selection, wrap only that selected handler's shared invocation: synchronous and awaited ErlangException failures receive WithStackFrame for the actual selected Handler:undefined_function with its three actual projected arguments, as a normal compiler runtime-call boundary would do. This provides an actual frame for a registered intrinsic/HOST callback that throws with Nil trace. It also preserves the normal source callback path: error/1 and ordinary nested call errors do not already capture this outer handler invocation boundary; error/2,3 and explicit raise traces are ExplicitStackTrace and WithStackFrame returns them unchanged. Never add a frame simply by guessing from the first frame value: equal recursive handler MFAs can be legitimate separate invocations. Ordinary direct invocation and existing source frames must remain otherwise untouched. A selected handler with explicit Nil/custom trace must stay Nil/custom; no blanket setting of ExplicitStackTrace is allowed. Tests must verify this concrete assumption against compiled source callbacks and registered HOST callbacks before promotion.

Compiler.Execution.CallRuntime and Expr.Call store their own out policy before invoking the shared method and awaiting. Their existing catch adds RuntimeCallFrames.Capture ONLY for Direct; UndefinedFunctionHandler rethrows the already captured actual handler invocation failure instead of adding the fictitious missing original MFA. The Expr.Call special non-registry routes (record predicates, literal load_nif/source hooks and existing loader handling) remain Direct and retain existing capture behavior. Runtime.ErlangApplyDispatch likewise suppresses only its synthetic requested-target frame when its own local policy says a handler was selected; all Direct behavior, including existing empty-trace capture and outer apply/3 behavior, remains unchanged. The common RuntimeCallFrames and Terms.ErlangException implementations need no change. Per-invocation locals naturally isolate concurrent/nested calls and require no ambient cleanup or long-lived marker storage.

Route inventory: normal source literal/non-tail external calls use Expr.Call; runtime/source tail transitions use Execution.CallRuntime; erlang:apply/3 uses ErlangApplyDispatch; external fun entries use the public registry Call and therefore receive central actual-handler failure capture without an extra missing wrapper. Raw BEAM import calls that already reach public registry Call share central selection/capture; their finite BeamExternalImports admission whitelist remains unchanged, so arbitrary unknown raw BEAM imports are NOT newly admitted. Source function-entry/purge/closure admission remains unchanged. HasExport/function_exported/safe external-fun decoding never invoke a handler. No missing local lexical function, badfun, malformed apply arguments, an undef deliberately raised inside an existing real callee, or invalid registered-name send is rerouted.
