# Exact-caller NIF image admission coordinator candidate 1

Source-only artifact based on artifacts/root-nif-image295-isolated/candidate. No Main edit, build, formatter, HOST execution, native call, Git operation or network mutation was performed. Existing 295 target/focus evidence does not validate these new sources.

## Bounded implemented operation

ReserveNifImageAsync captures the actual top ProcessContext code flow and verifies that its image has an active source lease. It does not infer a caller from an MFA string or accept a caller-supplied module/image argument. It verifies the registry belongs to that process runtime, awaits shared code-modification permission with mailbox control/cancellation handling, and then captures the exact registry generation under a short monitor scope.

Current callers must match the current image and descriptor SourceOwner or a registered body owner. Exact pending callers must match both the live pending ticket and its same CodeImage. Old-image callers reject before initialization. Pending phases must remain Staged or Running; Completed, Published and Retired cannot admit or commit an initializer. A source lease and the code-modification ticket remain owned for the complete reservation, including native initialization and failed-initialization cleanup.

Native OTP has a subtle wider branch: after checking the caller is not old, erl_nif.c selects module.on_load whenever it exists. A current-range caller while a distinct pending image exists therefore needs separate native observations. This bounded coordinator explicitly refuses PendingCurrentAmbiguous internally instead of attaching a different image or fabricating a native error contract. Exact pending-ticket calls are supported. An already attached target rejects Reload. An attached previous generation rejects UpgradeUnsupported; this revision cannot silently treat an upgrade as a fresh load.

InitializeAndCommitAsync invokes the supplied initializer outside the registry monitor and outside the permission ticket's short mutation monitor. Holding permission across this await blocks replacement/publication/purge writers but keeps ordinary registry reads available. Initializer result enumeration is materialized outside monitors because even an IReadOnlyList implementation can execute arbitrary code. The commit revalidates current/old/pending identities, descriptor identity and every captured body/source-owner reference, checks process cancellation/runtime halt, and atomically publishes the entire binding snapshot. This is atomic binding publication, not a completed installed module_info(nifs) implementation.

The initializer owns its resources until it returns NifImageInitialized. After return, this reservation owns the returned IAsyncDisposable until successful publication transfers ownership to the image. A thrown initializer must clean its own not-yet-returned resources. On cancellation, abandonment, generation mismatch or validation failure, returned resources are disposed outside monitors before the binding reservation, extra source lease and code permission are released. Primary and cleanup failures are both retained through AggregateException when necessary.

DisposeAsync before initialization closes the reservation idempotently. DisposeAsync during initialization requests abandonment and joins the actual initialization/cleanup driver. It does not pretend cleanup is complete, cancel an unmanaged callback or release code permission early. If commit has already linearized, disposal joins completion and does not unload the successfully committed image. A diagnostic initialization-flow marker rejects self/ancestor disposal instead of joining its own operation; it also rejects attempts to reacquire the same retained permission from an initializer or failed-owner cleanup. Failed cleanup still unwinds before permission release, and primary/cleanup failures remain visible. A future native loader owns and awaits the driver through its runtime lifecycle; this artifact does not introduce a fire-and-forget loader.

## Source changes and HOST contracts

Five files replace small baseline sections: ProcessContext.cs adds current-flow capture; ModuleRegistry.CodeModification.cs extracts guest-aware ticket acquisition; the permission and ticket classes add diagnostic retained-permission reentry checks; RuntimeActorDispatcher.cs isolates that diagnostic marker for newly created Erlang processes. No OnLoad.cs or ProcessRuntime.cs lifecycle/callback-fault source is changed. The lazy NifImageBindingStore is not modified, keeping the separate source-entry bridge work disjoint.

The marker is an AsyncLocal stack solely for reentry detection, never write authority. Host Task.Run descendants retain it so a callback cannot delegate a self-deadlocking write and await it. Newly spawned independent Erlang actors clear only this marker; otherwise inherited ExecutionContext would incorrectly classify their legitimate guest writers as reentrant. The actor-isolation helper returns the original delegate when no marker exists, avoiding an extra wrapper/task allocation on ordinary actor dispatch. These allocation properties are source construction, not a measured performance claim.

The separate HOST files cover no-caller/foreign-runtime rejection, current identity and reload, old-image rejection and unsupported upgrade, idempotent never-initialized disposal, replacement blocked across an initializer barrier while registry monitor reads remain available, abandonment joined through a blocked cleanup callback, deliberate generation mutation fault injection with cleanup and retry, self-disposal and cleanup self-join refusal, host-child retained-permission refusal, an independent spawned Erlang writer remaining usable, and exact staged pending-ticket image selection while current remains unchanged. The pending test manually enters an actual staged ticket's code flow; it is a managed coordinator contract, not proof that an Erlang on_load instruction invoked a native loader. Its native-owner cleanup is explicit because automatic pending retirement is not implemented by this overlay.
