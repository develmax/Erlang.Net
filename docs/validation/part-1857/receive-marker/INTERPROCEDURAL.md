# Local reference flow for receive markers

The verified direct marker patch is a useful code-generation base. It matches the complete marker opcode signature in four release methods and preserves the marked Equal observer module. The instrument audit uses the unchanged exact Part 1855 artifacts. No managed build or compiler invocation was made for this interprocedural audit.

## Scope from the release

Thirteen Different modules contain both a creator-only and consumer-only reference marker function. Their signatures include sixteen creator-only, twenty-two consumer-only and twelve clear-only MFAs. The independent superset contains forty-six modules and fifty-five creator-only MFAs. Co-occurrence is an upper bound. Method names, producer resolution, one unique translated reference, clear edges and result layout all need separate proof. Candidate modules include instrument, prim_inet, erl_prim_loader, inet_gethost_native, erts_internal, gen and erpc. See interprocedural-cooccurrence.json.

## Smallest role model for these origin-to-consumer chains

- Use stable identity for each lexical fresh reference binding and each already-bound formal. Record a graph point around normal branch edges and each statically resolved local call. Do not attach the fact to an Erlang variable name or a finalized BEAM register.
- Forward a token from the resolved make_ref/0 producer through regular dominance and actual-to-formal mappings. At a local non-tail call keep the caller binding on the success continuation. At a local tail call pass its proven argument roles without adding a caller continuation. Only known fresh origins plus receives in which every accepting remove_message is gated by that binding may seed marker use.
- Intersect forward availability with reverse reachability from proven uses. The minimal callee summary needs an accepted receive role, a forwarding role, and a borrowed formal active until some normal path returns to its caller's still-live binding. Add an explicit reverse edge from a non-tail caller continuation to the callee's return and translate a live actual back to its formal. This propagation matters even when the callee result has no Ref. Emit clear only on intra-function branch edges that leave that active region. SCC iteration handles recursive consume and comprehension loops.
- The observed instrument methods do not require forward provenance of a new Ref returned by a callee. That is a separate generalization. If later added, emit it only for proven fresh returned definitions. Pinned pr_successors explicitly excludes forwarding an already-known formal from its pseudo-return to every caller. The classic negative is a shared id/1 called once with a fresh bound reference and once with an arbitrary ordinary reference.
- instrument carriers/1 and allocations/1 create Ref after setup. The direct entry-marker route will need a definition-site hook rather than an entry special case. The result wrappers need a clear on the early count-zero branch and after the non-tail consume call, before constructing the return value. In carrier_info_receive/3 that final use forces Ref into Y across the call and makes the frame two slots. The consumers use the marker before the scan label and preserve it through successful messages until the final count branch. Clears at each remove_message would be wrong for this lifetime.
- The shared dispatcher is called with an ordinary Ref and returns {HistStart, MsgCount} with no Ref. Nevertheless, the successful caller keeps Ref. OTP translates it backwards over dispatch and comprehension returns. The invalid dispatcher and generator branches have no later use and clear. The inner comprehension also has a clear after its local recursive call before constructing its list tail. This is a consequence of the exact graph. Do not blanket-clear at call entry, local return or every successful receive.

## Source and runtime boundaries

Pinned beam_ssa_recv.erl scans statically local calls, success edges and returns, and considers exact erlang reference producers. Its external producer catalogue includes make_ref/0, alias/0-1, monitor/2-3, spawn_monitor/1-4 and spawn_request/1-5 with tuple projection for spawn_monitor. The existing bounded emitter only needs make_ref/0. The dispatcher invokes Gather through a function value. It must preserve the caller's live identity on ordinary completion, but it creates no provenance or receive edge through that dynamic dispatch. Passing a tuple that contains a reference cannot stand in for a translated formal identity.

The pinned scan retains the normal successor of a succeeded-body check and ignores exceptional successors. It skips try-tag landingpad edges. It relies on bounded marker recycling for orphaned exceptional paths. Initial scoped support should leave protected send and caught failure untouched pending direct graph and resource tests. Negative source witnesses include erlang:send_nosuspend/3 and the protected dynamic target in gen:reply/2. A verified ordinary send cannot prove that a caught remote send succeeded. The already validated direct code purger shapes are positive erts controls. Use kernel error_handler as a no_module_opt boundary. Its source explicitly needs dynamic weak dispatch, and pinned compile expands no_module_opt to no_recv_opt. Both source opt-outs remain independent from no_ssa_opt.

For unmanaged native and managed runtime acceptance, check a queued old same-tag message before reserve, two valid replies after it, caller-without-marker invocation of the same helper, the zero-count branch, count one and recursive count-many, timeout/error paths and retained queue order after final clear. Add a mixed source level identity-return control and an unresolved dynamic local/remote callable. Force collection with the opaque reserve slot before bind and with Ref held over the wrapper call. Exercise caught protected-send errors across more than marker capacity, then a successful request. Audit existing priority mailbox capability separately. Both clear and use of an absent marker must keep the ordinary mailbox scan behavior.

Instrument release execution can sample empty allocator/scheduler inputs for deterministic zero-count exits. Exercise nonzero consumers with deterministic fixture senders and use real allocator options only with stable assertions about result shape. Preserve immutable ERTS and managed receipts for values, structured errors and queued unrelated messages. Native admission, whole-function normalization and byte-exact files are independent measures.

Primary evidence is pinned beam_ssa_recv.erl scan_is/6, scan_add_call/5, scan_translate_return/3, pr_successors/2, plan_uses_1/4, intersect_uses_1/4 and plan_clears/2. The exact disassembly witnesses are raw-witness.log and Part 1855 frame-increase-audit. Existing marker opcode support, validator rules and register liveness should be reused. This package introduces no dependency on another implementation.
