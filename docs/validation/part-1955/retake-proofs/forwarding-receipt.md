# Preserve arguments forwarded into the first local call

The pinned Windows reference is OTP 29.1.1 commit ad05823719d77c8faee87348ea39513d4e2f99c5. The isolated compiler was constructed from frozen Part 1954 source 849729ef00f55f0ffc09c5bac934b92138b5a783fe48712b270eda87c94778e2 plus the 14 hash-verified Part 1955 compiler overlay files. The resulting 903-source closure was checked against the archived closure and linked overlay identities. Only the production LocalConstantArguments file and its already registered permanent fixture changed.

The prior 1963 extension treated every read of a known private input as a potential constant materialization inside eligible straight-line call-bearing bodies. The correction visits supported child expressions before their parent in source order. If the first evaluated call directly forwards the parameter from its incoming position into the same outgoing X slot of a declared local function, the new rematerialization rule leaves that parameter in its entry register. Earlier call effects, different outgoing positions and the older singleton rules retain their existing handling. The bound comes from source ownership and evaluation order. The patch contains no ASN.1 identities or generated names.

The eight-module replay recovers exact raw images for ECPrivateKey, EnrollmentMessageSyntax-2009 and PKIX1Implicit-2009. Compared with the uncorrected Part 1955 pilot, 1,660 common functions contain four changed bodies, all newly exact normalized, and zero losses. The restored bodies are the two decode_open_type_as_binary/2 implementations plus decode_universal_string/2 and decode_BMP_string/2. Compared with frozen Part 1954, all five earlier normalized gains remain across ct_master_logs:config_table/1, edoc_specs:throw_error/3, logger_olp:flush_load/1, erl_syntax_lib:split_lines/3 and snmpm_server:cbproxy_start/1, with zero additional changes or losses among the same 1,660 functions. Image identities appear in image-hashes.json.

Both isolated builds had zero warnings and errors, with zero files needing SDK layout changes. The expanded permanent fixture fails on the linked pre-fix compiler and passes with the patch. Its independent forwarding function has the same normalized allocate 0/2, local call and remote tail on pinned and fixed images. The pre-fix image instead allocates live X count 1 and reloads nil into X1 immediately before the local call. Seven pinned native fixture cases match, including direct forwarding, after-call rematerialization, open and escaped entries, FIFO effects and short-circuiting on error. A full corpus run is outside this isolated replay.
