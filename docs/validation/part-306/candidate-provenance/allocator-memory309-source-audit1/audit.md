## Exact public/helper semantics

| Input/operation | Pinned contract |
| --- | --- |
| alloc_info(A), alloc_sizes(A), A atom | get_alloc_info wraps[A], sends request, then unwraps exactly the matching sole result (erlang.erl13286–13288). |
| list argument | Cons or Nil enters is_list guard; request validates nonempty proper list, known allocator atoms and uniqueness BEFORE publishing any reply. []/unknown/nonatom/duplicate/improper list are badarg from system_info (erl_alloc.c3381–3424). |
| other argument | get_alloc_info has no matching clause: function_clause, not blanket badarg. |
| raw system_info tuple | allocator/allocator_sizes witharity2 traps to helper; arity3 requires local internal reference and valid allocator list, returns true after actual requests scheduled. memory_internal arity3 shares producer with sizes+internal flags (erl_bif_info.c2499–2535). |
| inventory | Native compiled allocator descriptors plus mseg_alloc,erts_mmap,alloc_util. Unknown name is invalid; known disabled/no-platform capability returns false, not an invented zero instance (erl_alloc.c3227–3273). |
| collector | Correlated selective receive {Ref,AnyMarker,InfoList}; number replies=no_aux_work_threads()-1. Requested allocator order retained; numeric instances sorted ascending; atom instance names prepend named pairs. No marker uniqueness validation or collector timeout is added by original (erlang.erl13289–13327). |
| memory/0 | Exactly total,processes,processes_used,system,atom,atom_used,binary,code,ets in that order, after real allocator blocks plus allocated_areas aggregation; system=total-processes (13021–13035,13101–13271). |
| memory(atom/list) | Snapshot/capability check BEFORE validating names/elements; notsup can precede invalid key or []. Valid list preserves order/duplicates, [] returns[] after successful snapshot. Other outer types immediate badarg (13064–13088). |
| improper memory list | Cons passes outer guard. Valid head then nonlist tail gives function_clause in memory_1; invalid earlier head gives badarg first. Do not eager-validate wholelist. |
| maximum | Absent get_memval clause on this pin: badarg when snapshot supported, notwithstanding stale prose mentioning instrumented mode. |

Allocator result shape matters: sys_alloc sizes and alloc_util sizes can legitimately contain instance0 empty info, because these particular original branches actually return NIL. That is not permission to synthesize empty info for absent CLR allocator providers. Named mmap instances and disabled false remain distinct. Native values fluctuate and are not expected SDK constants.

## Current reusable facts and real gaps

`SequenceTraceRegistrations` has no allocator/allocated_areas dispatch. `NifNativeAllocationOwner` owns real NativeMemory pointers and once-only cleanup, but records only pointer identity, not requested byte count; no aggregate instance/provider/categorization. `BitString` has exact immutable byte arrays and sharing through ByteView/FromOwnedBytes; it has no runtime ownership token, and several values can reference the same storage. `AtomNameRegistry` is process-global across all ProcessRuntime instances, holds names permanently, and counts names; Count/string lengths are not memory bytes. Process dictionaries, mailboxes, module tables, ETS and generic Cons/Tuple allocations have no retained byte ledger. Global CLR counters cannot distinguish these categories or isolate embedded runtime instances.

The307 distribution proposal introduces a real queued-storage charge derived from owned payload/vector/descriptor storage, counted per queue entry. It is a bounded implementation-specific queue charge, not unique resident bytes, atom/code/process storage or a global allocator backend. Reusing its numeric value as memory(total) would invent coverage.

## Smallest useful implementation boundaries

1. Port get_alloc_info/mk_res_list/insert_info/insert_instance/receive_allocator as an INTERNAL correlated reducer with a producer contract carrying an actual finite provider identity list. Test real selective mailbox retention, out-of-order numeric instances, named instances, disabledfalse, invalid producer list/error order, cancellation/death. No public helper registration while no successful real producer exists. One test provider is HOST evidence, not an invented production allocator.
2. Extend existing NIF allocation owner with pointer->requested-bytes records and checked current/peak allocation metrics, updated atomically with successful allocation tracking/free/reclaim under its real invocation/lifetime gate. Allocation failure must leave metrics unchanged; registration failure must free native pointer; owner cleanup must return count/currentbytes tozero. This creates the smallest REAL allocation source, but only native NIF requested payloadbytes (not malloc usable size/CLR heap/all-runtime memory). Bind the owner to its actual runtime/image before aggregating; current native-runtime association remains incomplete. Keep this as internal backend foundation, not erlang:memory or fake eheap_alloc.
3. For all four public APIs, choose and implement an actual guest allocation domain, with storage ownership identity and deterministic retained/reserved accounting across binaries/process roots/code/ETS/atoms/infrastructure. A coherent managed profile can report guest-domain allocated byte capacity and occupied bytes if those buffers/arenas are REAL and actually used by execution. It must exclude CLR object headers/JIT/hostallocations explicitly; cannot call an arbitrary per-object tariff actual CLR memory. Static global atoms require one VM-domain scope or explicit shared-global provider rather than per-runtime double counting. Shared binary storage counted once per domain with actual reference/lease ownership; incoming external Term graphs need an import/share rule. Live external Term references and shutdown lifetime must be specified before reclaiming backing storage.
4. Add provider request/instance results and snapshot aggregation only for those real domains. Code/ETS/atom/process categories cannot be filled from unrelated counters. Register public helper/API only when real successful supported paths exist, with explicit profile limitations and original validation/shape/protocol comparisons; do not add always-notsup exports to inflate readiness. Full nine-key memory completion needs all categories; a single NIF provider does not finish it.

Proposed source seams: new internal AllocationRequest/AllocationReply/AllocatorResultReducer and semantic names in Runtime; later actual RuntimeAllocationDomain/owned storage leases, plus NifNativeAllocationOwner bookkeeping. Existing selective receive and runtime lifecycle can be reused. Initial reducer+NIF byte ownership is a bounded meaningful increment; broad guest-domain migration is a separate architectural change, not an afternoon wrapper around GC.GetTotalMemory. No new dependency or C algorithm is needed.
