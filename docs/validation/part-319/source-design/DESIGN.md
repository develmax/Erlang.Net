#319 proposal: connect the actual guest PID-send routes to owned distribution output

Source audit only. No implementation, Main/Git mutation, build, SDK, original VM, native or network execution. Base is the exact318 isolated composition source-resource-closure.json 7B8C0913A6E46324BF8A40DBD8EB86105990AA6DA76B35EF9BA294E7A44D0C03; Main318/full is owned by Root. Public API presence must remain unchanged and is not semantic completion.

## Finding and priority

There is no existing guest pending/autoconnect send dispatcher to reuse. RuntimeDistributionPending.BeginPending manages handles/generations, but an entry contains no pre-connect packet queue or readiness completion. DistributionConnectedEntry creates its HostDistribution queue and ordered sequencer only when AdoptConnectedOwned succeeds. RuntimeNodeKernelRequest is a synchronous gen_server-call retry helper for monitor/disconnect requests; it is not the native auto_connect asynchronous protocol. The only auto_connect implementation-like spelling found under production sources is a primordial atom entry. Existing manual connected enqueue APIs are genuine owned transport machinery, but guest sends do not call them.

The higher-value concrete bug precedes pending support: erlang:send/2 and registered erlang:'!'/2 call ErlangOperatorValues.TrySendAsync. That function awaits only port operations; a PID falls into synchronous Send, then ProcessRuntime.SendTraced, whose lookup is solely the local processes dictionary. A remote PID therefore returns the message without any packet even when its actual controller is connected. The compiled source `Target ! Message` already awaits TrySendAsync in Compiler/Execution.cs, so it inherits the same gap. The real BEAM Send opcode additionally calls synchronous ErlangOperatorValues.Send directly in BeamRegisterInterpreter and will still be broken unless explicitly routed through the async guest path. Native record defaults/guards disallow !; those are not runtime send routes needing a new transport path.

ProcessAliasRegistrations has a related concrete bug: send/3 with [noconnect] immediately returns noconnect for every remote PID based on node inequality, including a currently connected target. noconnect means do not establish a connection; it does not prohibit sending on an existing one. The same shared caller carries nosuspend/priority, so adding an unconditional capacity wait to TrySendAsync would introduce a new send_nosuspend regression. These option branches must be accounted for in the bounded PID implementation rather than silently ignored.

318's following SEND was intentionally the real owned queue helper, isolating group-leader publication. It did not prove a guest send. A new cross-API HOST must call actual registered group_leader/2 followed by actual guest send/2 and generated !, then inspect controller packets in order.

## Exact original contract

All native references below are from git show OTP29.1.1/ad05823719d77c8faee87348ea39513d4e2f99c5, not the modified OTP working tree; numbered exact excerpts and full-blob hashes are frozen alongside this proposal.

* bif.c2381–2455 remote_send calls erts_dsig_prepare with connect/no_suspend, distinguishes not-alive/not-connected, would-suspend, connected and pending; connected/pending actually call erts_dsig_send_msg. Source tracing/saved-call accounting occurs once after the remote operation is accepted by this path.
* bif.c2459–2505 do_send distinguishes local PID, old-incarnation external PID pointing at this node and remote PID. Dead local PID accepts/drops. Old-incarnation external PID pointing at this node also accepts/drops (with native logging), not group_leader's badarg. Do not cargo-cult the group-leader target-death rule.
* bif.c2697–2778 validates the entire send/3 option list before dispatch, including improper tails; bad options are badarg with native badopt information. Successful send/3 returns ok; noconnect and nosuspend are distinct result atoms. bif.c2801–2804 and2845–2892 route send/2 through do_send(connect=1,suspend=1,prio=0), returning the original message on success and no-connect, preserving badarg/system_limit branches.
* dist.c1573–1590 gates wire seqtrace token by negotiated BIG_SEQTRACE_LABELS or the legacy 28-bit label range. dist.c1592–1711 advances sender seqtrace once, selects legacy SEND or SEND_SENDER using negotiated flags, adds a token to the corresponding *_TT form, or uses ALTACT_SIG_SEND for priority when negotiated. Sender PID, token and payload are real values; no constant seqtrace token is acceptable. dist.h freezes the actual flag/alternative-action bits.
* bif.c4914–4970 group_leader and dist.c3216–3300 erts_dsig_prepare allow PREP_PENDING as well as PREP_CONNECTED. dist.c5713–5759 erts_auto_connect atomically sets IDLE to PENDING and sends exactly {auto_connect,Node,DHandle} to net_kernel. It is not gen_server:call. Missing kernel aborts that exact pending generation. This requires entry-owned pending output and lifecycle, not merely a lookup or awaiting a future connected object.

## Proposed bounded implementation after review

Prioritize connected PID guest sends. Keep unknown/disconnected/pending remote behavior explicitly partial in this milestone; no OS networking, connection initiation, handshake buffering, named remote destination or remote-alias completion is claimed. Preserve existing local/port/alias paths and public embedding synchronous helpers, documenting that the latter remain outside the async guest guarantee.

1. Add a narrow internal connected-PID publication route in RuntimeDistributionPending, capturing entry/connected/connectionId and actual caller under the runtime gate, as318 does. Reuse existing EnqueueConnectedOutputAsync's lease, producer ticket, snapshot, ownership and PublishOwnedPacket path; an internal captured-generation overload can remove the need to manufacture a guest-visible handle. Alternatively factor the existing owned packet publisher narrowly. Do not duplicate a detached delivery service or use unowned enqueue. Generation retirement can drop an accepted message and must not replay into a replacement; caller cancellation on the current generation must propagate. Bind the catch filter to the exact captured entry/connected/id; do not catch arbitrary cancellation into success.
2. Return a small internal result distinguishing NotConnected, Accepted and WouldSuspend so option adapters can map actual states honestly. One enum/type per file. Existing connected lookup plus reserve/admit must be one gate-owned decision; a preflight connected boolean followed by unbound send is racy. NoSuspend must use immediate sequencer reservation and nonblocking capacity admission, never await queue space. A failed immediate attempt must release its ticket and leave no queued packet. NoConnect allows the captured existing connection and returns noconnect only when no supported connection exists, after full option validation.
3. Connect registered send/2 and !/2 plus the generated source operator via TrySendAsync; connect the BEAM Send opcode to the same awaited guest operation and retain original message as the result/register0. The public send/3 and send_nosuspend PID paths need the same connected dispatcher/explicit result mapping. Other destination kinds retain their current bounded behavior; do not silently advertise a complete send/3 implementation.
4. Select PID control using captured negotiated flags: DOP_SEND/empty cookie versus DOP_SEND_SENDER/actual sender; corresponding trace variants carry the actual sender token. Existing serialization validates these shapes and sender-negotiation flag. Priority must follow the pin's ALTACT_SIG condition rather than always injecting an ordinary SEND when that capability is negotiated. Add the exact domain constants if absent. Preserve native fallback when that priority capability is absent. The SDK profile currently accepts flag bits beyond its named constants, so merely omitting an ALTACT constant does not prove the bit cannot be negotiated.
5. Advance SequenceTracing.Sent and record ProcessTracing/SavedCalls exactly once in the admitted operation's source-guided phase. Build the token with SequenceTraceToken.ToTerm, not a reconstructed approximate tuple. Respect legacy small-label gating when BIG_SEQTRACE_LABELS is absent. Review async retries/capacity loops so encoding retries do not increment serial or emit duplicate tracing. Native no-suspend may have already encoded/accepted a signal before yielding in some paths; the SDK immediate admission policy remains a documented bounded queue adaptation and needs explicit native/source evidence rather than a claim of scheduler byte parity.
6. Validate ownership and PID shape without changing dead-local/old-incarnation acceptance. Resource/function payload encoding failures must retain existing error boundaries; do not relabel all ArgumentException/NotSupportedException as badarg or system_limit without a source-backed rule. Keep oversized payload policy/errors separately bounded. No changes to default registration count, historical case expectations/order or six exclusions.

Implementation can remain a small runtime/BEAM adapter change with a permanent HOST group and narrowly appended original cases. No implementation is authorized by this document alone; Root reviews the frozen proposal first.

## Meaningful validation, not currently executed

* Historical RED: actual connected controller, public registered send/2 returns its exact payload but queue has no message. Repeat actual registered !/2 and generated source Target ! Message. Preserve source/runtime bindings so a helper SEND cannot accidentally satisfy this RED.
* GREEN: both negotiated normal PID control profiles, exact payload and sender/cookie; generated operator and actual BEAM Send opcode if a supported original fixture is available. Public group_leader/2 -> registered send/2 -> generated ! from one process must emit opcode7 then two correct payload packets in order.
* Real queue pressure: async send waits, draining one slot releases exactly one publication; nosuspend returns nosuspend/false with no deferred packet; connected noconnect returns ok and emits once; disconnected noconnect returns noconnect without creating an entry/notification; option errors/improper tails win before state classification.
* Kill/join blocked producer; halt with blocked output; retire/reconnect generation with no replay and fresh progress; genuine cleanup/resource drain. Preserve inbound,318, admission/publication and seqtrace HOST groups.
* Actual seqtrace token serial advances once across waiting/retries, sender and LastCount/label exact; legacy small-label omission versus BIG_SEQTRACE_LABELS; priority control flag selection both negotiated and fallback. Record actual token/payload/controller bytes; do not assert only nonempty output.
* Paired ordinary cases for local/dead-local/stale self-node/invalid shape/option result rules remain small and deterministic. Extend the already-reviewed original two-node collector source with actual public send/2, ! and noconnect delivery/probe ordering; retain raw original observations and SDK controller HOST as separate roles. Original wire-byte equality requires a separately reviewed native-controller capture, not a stable projection substituted for raw bytes.
* Target/format/token checks, actual historical RED/fixed GREEN and full validation are required later. No prediction of final test count or semantic readiness percentage is made here.

## Why full pending/autoconnect is a later foundation

It is feasible without an OS network implementation if a real guest net_kernel/owned HOST bootstrap can consume the exact auto_connect message and later adopt a controller. It is not a small reuse of present send/2, because that path has no pending support. A correct foundation must own pending signal records at the entry/generation before a connected sequencer exists, bound queue capacity, carry an acceptance-time local-node snapshot, retain payload/resource ownership, and encode against final negotiated flags. After pending admission the entry owns the accepted record: caller death must not withdraw an already accepted signal. Waiting only for connection before returning would change native acceptance behavior and can deadlock guest kernel scenarios.

The transition from IDLE to PENDING and exactly-once {auto_connect,Node,DHandle} notification must share the real gate and kernel checks. Existing BeginPending handle generation, node capacity and retirement can be reused, but no unsolicited public pending handle or repeated notification should leak. Abort/kernel death/halt must drop and drain only the captured generation; replacement must never receive stale records. Connected adoption must transfer pending records and signal order before later live sends can overtake them. Unnegotiated payload-size accounting, deferred function/resource lifetimes, acceptance vs producer cancellation and entry-owned sequencer transfer need explicit controls. These are concrete missing semantics, not reasons to add network code or fake an always-successful connector. Complete these after the connected public-send gap is closed and independently verified.
