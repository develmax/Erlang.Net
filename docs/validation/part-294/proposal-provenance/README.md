# Original OTP output-pressure observation proposal

Source-only artifact, not executed or published. New scope: three independent unnamed fresh original OTP-29.1.1 VMs with explicit +zdbbl 1 +S 2:2. Historical Part278 queue7 is neither changed nor rerun. No Main edit, build, Erlang compile, native execution, Git mutation, workflow dispatch or network request was performed.

## Concrete scenarios

1. same_controller_replies fills the output until send/3 with nosuspend actually refuses admission. The same process owns both output controller and input handler. It injects a missing-target LINK and UNLINK_ID and reports both put_data results before the owner ever sends a get_data command. This causal command barrier tests the self-drain deadlock directly. Later controlled drain captures raw output segments, byte packets, decoded controls and untouched payload tails until exact noproc EXIT and matching UNLINK_ID_ACK are observed.
2. producer_death_then_writer observes a real ordinary sender in suspended status while output is busy, kills it and receives its local DOWN before any drain, then observes a second sender suspended. Controlled drain releases native capacity; the second sender must return, and a second drain captures its queued output. All packets are kept, including a possible killed sender marker. Pinned remote_send calls dsig_send_msg before interpreting native YIELD as SEND_YIELD_RETURN; the nonfragmented marker source predicts an already admitted packet before return-suspension. This is not the SDK hard-budget pre-admission cancellation state. No absence assertion is made for the killed native sender's payload.
3. terminal_public_free first observes the remote link in the target's real local link inventory. It then fills the output and requests target exit. is_process_alive=false, process_info=undefined and local monitor DOWN are recorded while no output drain command has been issued. Only afterward does the controller drain the terminal EXIT packet. Public lookup and local DOWN are the portable projection; C# host Done/Unwound tasks are not called native Erlang monitor semantics.

Busy is established by actual native behavior, not a timer or chosen byte count. The probe captures configured dist_buf_busy_limit, native dist_get_stat snapshots, full identities/handles, suspended process status/current function/stack, monitor messages and raw wire buffers before and after controlled release. Polling only yields until a concrete process-state predicate is true; every poll has an independent monotonic deadline. Fill/drain counts and all receives/cleanup are bounded. Owned children are monitored and killed/joined during cleanup; the separate fresh VM process has the reused collector's 45-second timeout and raw process-tree cleanup.

## Explicit limitations

Only one distribution connection is used per scenario. Two-channel terminal ordering, controller death during a blocked sender, generation changes, malformed/fragmented input, native network transport and broad runtime shutdown are deferred. This is a bounded observation proposal, not an exhaustive pressure suite or proof of speed/allocator/queue-capacity parity. Large packet artifacts are bounded but retain duplicated raw segment/byte representations deliberately for independent inspection.
