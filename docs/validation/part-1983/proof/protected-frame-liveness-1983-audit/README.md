## Full release scope and strict source intake

The second census covers all 2,787 Part 1981 functions with a single untrimmed Y frame wider than one and one handler. The existing allocator model agrees with the reflected production plans or refusals in all 2,787 cases. Admitting all empty-handler atomic projections would shrink 150 functions across 101 modules. The pinned singleton width is closer in 124, incomparable in 25 and farther in one.

The farther case is cover:do_export/4. Its generated normal path moves the call result into Y5 just after TryEnd closes the Y5 tag and projects that register in separate tag-dispatch arms. Pinned saves the call result into Y0 before closing Y5 and derives a different switch/projection schedule. Because the implementation colors physical Y roles wholesale, the newly admitted atomic alias cannot involve the reserved handler slot even after closing it. With that restriction the model finds 108 smaller frames in 78 modules, 93 closer and 15 without comparable pinned singleton widths. Requiring the existing ordinary FindEntryFrameAllocation gate reduces production scope to 86 functions across 64 modules. There are 75 measured closer, including 5 reaching the pinned width, and 11 without comparable widths. None of the 108 previously has a matching body with local labels normalized, either retaining or ignoring register type operands. The original 512 exact modules remain controls.

Representative ordinary-gate predictions reaching the pinned width include snmpa_get:try_get_instance/2 (6 to 5), erl_tar:add_directory/5 (7 to 6), edlin_context:extract_argument/1 (5 to 4), megaco_codec_meas:detect_version/4 (6 to 5), and mod_auth:store/2 (5 to 4). These are physical frame-width predictions. Function-body or whole-file gains need a compiled candidate.

The existing unprotected and fallback planners use their original paths. Forward and reverse patch applicability checks passed on private exact copies. No C# compilation, fixture run or corpus run was performed for these patches.
