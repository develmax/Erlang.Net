## Exact pinned source and boundaries

Licensed authorities are reused byte-for-byte from source3 and bound in `baseline-bindings.json`. In pinned `io.c:7626-7679`, Add takes the driver-list lock before publication, installs recursion TSD only on its first acquisition, calls real init, restores the actual `dp->next` boundary on failure, and clears TSD/unlocks after completion. `io.c:7683-7720` allows nested removal under that same physical caller; target ownership is distinct from caller ownership and dynamic removal is refused. This packet does neither: dynamic init only waits/fails, linked additions run in start, removals run in stop, finish contains no driver-list API.
