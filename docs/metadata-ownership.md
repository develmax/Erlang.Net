# Caller-owned metadata Term graphs

This clarification describes the existing C# extension boundary; it adds no owning API. ModuleCodeDescriptor snapshots function/export/native-record collections and copies its fingerprint by value. Compilation and Attributes retain the exact supplied Terms. NativeRecordDefinition snapshots field/type collections; default values and NativeRecordFieldType.Syntax retain their exact Terms. Read-only collections do not transfer native lifetime.

These caller-supplied graphs remain borrowed. Code supplying physical/native Terms must retain their genuine source frame/borrow, image/literal lease, or appropriate Host custody until every use finishes, including registered module-info/default/type consumers. Registration and C# references do not create physical GC roots or extend that custody. Host backing custody alone does not preserve arbitrary source process-cell headers. Dispose native Host wrappers/scopes before their VM. After custody ends, actual physical/native access must refuse stale storage; identity-only managed observations need not all fail. Use detached managed values when metadata must outlive its source.

Term kinds and exact values remain unrestricted by this clarification: no atom-only whitelist, ETF roundtrip, implicit native magic-resource conversion or blanket container root is introduced. Preserve full nested values, arbitrary binary bit lengths and caller resource identity while legitimate custody is live. The API does not promise arbitrary live C# metadata survives supplier retirement.

Canonical Erlang source and BEAM loading are separate producers. Source/BEAM Attr/CInf metadata is detached code-constant data; pinned OTP serializes the complete terms into Attr/CInf ETF image bytes. Keep the full decoded values/policy, not an atom-only subset. Omitted canonical record defaults are prepared under their actual defining image: local old-code and external CURRENT lookup have distinct replacement/purge semantics. A public borrowed container does not itself establish either image lease.

The permanent MetadataBorrowed316 control covers both runtime profiles, exact Term reference preservation, live caller-frame native binary/atomics magic-resource access, ordinary/writable/unaligned views and explicit producer/Host release. It requires real source collection/provider/destructor retirement while metadata remains referenced, then actual binary/header reads must reject stale storage. Staging those tests does not certify execution or whole compatibility; final build/runtime/CI evidence is recorded separately.
