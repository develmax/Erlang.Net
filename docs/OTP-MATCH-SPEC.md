# Match-spec compiler and test prototype

Baseline: OTP-29.1.1/ad05823719d77c8faee87348ea39513d4e2f99c5. Sources inspected through the pinned Git object: erts/preloaded/src/erlang.erl, erts/emulator/beam/erl_db_util.c, and erl_map.c (flat-map duplicate-key construction). Existing immutable terms, term comparison, numerical operators and pure managed BIF callbacks are reused; no external dependency or production BEAM.

Implemented: ordered clauses; canonical sparse `$N` bindings including `$0`; repeated exact comparisons; wildcard and nested tuple/list/map-subset heads; trace argument arrays/proper lists/prefix wildcard tails; pure guards and operators; `$_`, sorted `$$`, `const`, double-tuple/list/flat-map construction; last table body result/default true; guard rejection and body `EXIT`; trace message selection/default true/false and return/exception flags. Trace test accepts an improper subject list by collecting its cons heads, matching the pinned wrapper. `caller` returns undefined only in test mode.

Constructor/order contracts: list head before tail; tuple and ordinary function arguments right to left; short-circuit operands left to right; flat-map values right to left, then keys right to left. Flat-map key collisions keep the later original entry, as erts_usort_flatmap does. Source-derived diagnostic strings and their builders are owned by MatchSpecDiagnostics. The pinned implementation has no active WARNING calls, so supported programs return an empty warning vector.

Shared production API: MatchSpecCompiler.Compile returns an immutable validated MatchSpecProgram or ordered errors. MatchSpecProgram.Run is synchronous, with RunAsync as a completed ValueTask wrapper. IMatchSpecTraceActions explicitly declares support and executes real synchronous trace actions. RequiredTraceActions supports installation-time checks. Production tracing must additionally reject event-incompatible actions, because generic trace compilation uses the test call/trace-op dialect. Test mode never invokes a production adapter. Pure guard invocation bypasses ModuleRegistry call tracing and saved_calls. Native match-only is_integer/3 is handled directly with actual managed integers.

Partial scope: test-mode native fake destructive sequence-token/control-word/trace configuration operations, display/dumps, caller_line/current_stacktrace and production actions without a real adapter are rejected with `{not_supported,{match_spec_operation,Name,Arity}}` before matching. They are never accepted as effective no-ops. Extended unsupported-operation grammar, complete native `%T` formatting, compiler optimization/lint edge ordering, physical resources and the native match VM are not claimed complete. Managed nesting is bounded at512 and expression map construction at32 entries; native HAMT traversal/effect order is unavailable, so larger constructed maps raise explicit system_limit (literal large maps can use const). Sparse variable numbers above Int32 raise the same explicit managed resource limit rather than relying on native integer-overflow behavior. Full table/trace match-spec compatibility remains partial.

Validation: 55 permanent source fixtures, one direct match_spec_test/3 MFA route, and32 concurrent host executions prove immutable-program reuse, actual production message delivery, flags and test/production isolation. Baseline audit preserves the ordered4132 sources, expected outcomes, source/generated hashes, caller contexts, compiler policies, finite stdout/stderr bytes and alternatives;132 diagnoses and6 known oracle exclusions remain. Full isolated validation and original comparison are recorded separately; parent owns original proof and integration.

Consolidated source attribution is in OTP-PORTS.md. No source license banners or LICENSE.local.txt are introduced.
