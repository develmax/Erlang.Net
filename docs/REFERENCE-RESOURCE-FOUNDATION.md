Plain ReferenceTerm objects, even with identical words, cannot directly acquire payloads. Consumers acquire an IDisposable typed lease; disposing one lease releases only that strong owner and does not invalidate other reference terms/copies.

The registry is per runtime, with weak entries keyed by plain identity terms; keys carry no payload. A live resource term or lease strongly holds its entry/payload. Entry holds the registry but the registry does not strongly hold entries. Byte arrays and reference strings carry numbers only and do not retain a payload. Dead weak entries are purged on lookup/count/create; normal managed arrays/code snapshots require no native destructor call. Counts report actual infrastructure entries, not native memory/GC statistics. Runtime halt/dispose closes every live entry and clears the table; lease reads then reject and future creation fails. Existing public captured PreparedBeamImage values are not revoked; their pre-existing HOST API ownership remains separate from this reference capability.

Identities use crypto-random native-number fields with the existing MagicMarker lane, never the ordinary make_ref or PID marker lane. Exact numeric collisions in one registry are checked before insertion; no global resource table/static lookup is introduced. Foreign runtime subtype owners cannot acquire locally; owner-aware decoders only look up their own VM. Identity wire reuse across independent same-node/creation runtimes is not a transport/authentication boundary and this is not connected distribution.
