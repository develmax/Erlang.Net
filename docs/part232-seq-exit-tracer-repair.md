# Original232 dying sequential tracer / linked EXIT failure

Read-only audit, 2026-10-14; source pin OTP-29.1.1, ad05823719d77c8faee87348ea39513d4e2f99c5. No Main, frozen candidate, source fixture or expected outcome was changed.

Original evidence is artifacts/part-232-initial-mismatches.json, case erlang-seq-exit-dying-tracer-self-counter-suppression. Native outcome is {error,error,{badmatch,{serial,{3,11}}}} while SDK returns independently expected {ok,done}. The source asserts serial {3,10} and later token {1,child,10,P,3}. The initial serial assertion fails on native; the later assertion was not executed, so its native value below is source-derived rather than separately observed.

The dying child's sequential tracer is its own PID. This is different from an alive process sending to itself while remaining the tracer. Native begins process exit by selecting ERTS_PSFLG_EXITING in erl_process.c:13487-13511. Link fanout occurs in ERTS_CONTINUE_EXIT_LINKS, erl_process.c:14544-14555, invoking erts_proc_exit_handle_link. That handler forwards SEQ_TRACE_TOKEN(c_p) and the real dying sender to erts_proc_sig_send_link_exit at erl_process.c:14068-14083. The wrapper calls send_gen_exit_signal with that token and sender at erl_proc_sig_queue.c:2579-2596.

The producer derives c_p from sender, computes seq_trace = c_p && have_seqtrace(token), and invokes seq_trace_update_serial(c_p) before copying the token at erl_proc_sig_queue.c:1627-1703 and1749-1753. Serial update first obtains the current system tracer (erl_trace.c:920-943). erts_get_system_seq_tracer validates an existing tracer with trace_status/undefined; if enabled returns remove, it replaces the system tracer with NIL (erl_trace.c:476-494). Default erl_tracer_nif enabled first tests process liveness and returns remove for a dead tracer in trace_status mode, BEFORE the tracer==tracee suppression (erl_tracer_nif.c:121-149). enif_is_process_alive on the scheduler uses erts_proc_lookup (erl_nif.c:2323-2338); that lookup returns NULL for a process in EXITING state (erl_process_lock.h:1151-1158).

Consequently the dying self tracer is invalidated before serial update. A NIL tracer does not suppress update: seq_trace_clock increments from10 to11; sender becomes P; serial becomes11; lastcnt remains3. The copied link-exit token is source-derived {1,child,11,P,3}. Output emission finds NIL tracer and produces no sequential trace notification (erl_trace.c:968-990). The actual trapped EXIT still propagates its immutable token to the receiving parent. This precisely explains the observed native {serial,{3,11}}; it does not depend on scheduler timing, synchronous tagged-spawn clock or timer undefined sentinel. Timer go preserves the child token, which is created after the receive.

Concrete managed defect: SequenceTracing.LinkedExit uses cached field tracer?.Equals(sender.Self) to bypass Advance. Runtime.Terminate removes the sender from processes before calling LinkedExit, but this bypass avoids the normal Tracer() liveness refresh used by Advance. The appropriate narrow repair is to call Advance(sender) unconditionally for a linked process exit, retaining its existing token-null/live-tracer logic. Tracer() then clears the already-dead sender and increments the clock. Output and immutable send-pending/copy behavior remain unchanged. Do not blanket-remove alive self-tracer suppression from Advance and do not introduce a receive/system preserve workaround.
