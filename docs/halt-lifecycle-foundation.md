Transfer is a sealed Exception separate from ErlangException, with runtime identity. Runtime outer execution and initializer work bypass generic error mapping for matching transfers. ModuleRegistry guards entry and async/sync return boundaries; interpreted/generated Execution polls context reduction; context receive guards before/after actual receive. TryExpressionExecution skips after for matching current-runtime transfer or actual current-runtime Stopping/Stopped, and catches only ErlangException as before. Foreign-runtime transfer does not suppress an unrelated runtime's after. GenServer/Supervisor matching transfer avoids startup failure remapping; GenServer skips user terminate callback when logical VM stops. Code-purge worker rethrows matching transfer instead of constructing clr_error. Existing normal disposal/hibernate/source exception behavior remains unchanged outside actual new halt state.

Arbitrary C# code can catch System.Exception, execute finally, or block forever without checkpoints. The API cannot safely force such code to stop. Logical completion therefore differs from physical quiescence.
