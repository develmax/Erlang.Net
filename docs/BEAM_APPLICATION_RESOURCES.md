# Opt-in BEAM application resources

This SDK V1 route packages concrete data. It does not load/start an OTP application, apply configuration, implement application_controller lookup/defaults, or provide code:priv_dir. Pure OTP module bodies stay Erlang; the original compiler and file:consult parser are build-time dependencies. Packaged BEAMs execute in our .NET runtime.

Use the `ErlangBeamApplication` item once, with `ApplicationName` and `Version`; its filename must be Name.app or Name.app.src. The app.src must already contain concrete terms. Descriptor bytes are copied unchanged to `lib/Name-Version/ebin/Name.app`. The descriptor modules list must name exactly the explicit admitted ErlangBeam images, in the descriptor's own order. Zero modules supports a data-only bundle. No template expansion, module-list generation or version substitution occurs.

`ErlangBeamPriv` and `ErlangBeamConfiguration` each require a portable `LogicalPath`. They are copied under priv and config respectively. Configuration declaration order is recorded; files and values remain unmerged and unapplied. Source/physical paths are relative to the explicit `ErlangBeamApplicationSourceRoot`, which must be disjoint from the intermediate application output. The source compilation root may be a separate tree. Fresh source compilation with runtime admission uses explicit DeclaredIncludesV1; application mode never silently changes source policy.

Build properties name the exact installed original compiler/runtime, provenance receipt and all three hashes, plus absolute dotnet host and build-tool paths. The existing provider admission checks the pinned compiler installation. The CLI route is `--application-request ABSOLUTE_JSON`; the original one-argument source route remains separate. [HelloBeamApplication](../examples/HelloBeamApplication/README.md) demonstrates the item declarations and an explicit .NET call.

The build privately snapshots descriptor, BEAM, priv and config bytes before launching resource children. It uses the admitted original file:consult driver for data parsing, then independently validates the returned ETF shape, application/version, module set and ordered config. Native logs, full failure ETF and owned-process receipts remain in intermediate stages. The public application-resources.json contains relative paths, kinds, byte counts and SHA256 identities. Private beam-application-state.json additionally records ownership, provider/tool/parser identities and retained parsed ETF.

A cache hit starts no original resource child and preserves accepted final file/state bytes and timestamps. It still writes a fresh diagnostic stage and input snapshot. A declared byte/order/tool/driver/provider change invalidates the resource identity independently from source compilation. Missing owned outputs can be rebuilt; edited or unowned destinations are refused. Stale deletion is limited to unchanged previously owned files; unrelated sentinels survive. Resource failure does not accept a new final state. Multi-file promotion is not atomic against arbitrary IO failure.

Application mode reserves SDK-computed copied None/Content destinations, rejects portable case/file-prefix collisions and refuses custom placement of selected BEAM inputs. Only verified original None identities are relocated. Source diagnostic Modules/beam-build-state.json remains separate. FileWrites registers owned final files/state for Clean, without a wildcard over unrelated sentinels. App mode inactive leaves ordinary retained/source placement unchanged.

Paths use exact physical casing without reparse ancestors and portable logical destinations. V1 bounds are 1 MiB request JSON,256 declared input files,16 MiB/file and128 MiB aggregate. These are SDK policies, not claims about original application_controller resource acceptance or error metadata. Local validation and frozen runtime evidence are distinct from GitHub CI/publication; no new publication is authorized for this increment.
