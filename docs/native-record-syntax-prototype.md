## Actual coherent slice

Native declarations use -record #Name{...}. and can coexist with tuple records. Native names support uppercase/keyword spellings; defaults support literal containers, arithmetic and signed floating zero. Omitted fields without a default are required; local construction emits a compile diagnostic for a missing required field. -export_record and -import_record drive actual local/external semantics. record_info and field-index syntax are rejected for native records. Duplicate exports/fields/definitions are checked, but complete annotation/type/lint warning/error precedence is not claimed.

A NativeRecordExpression and NativeRecordPattern preserve native construction/access/update/matching throughout parsing, binding/closure traversal, guard handling, comprehensions and generated C#. Ordinary tuple source generation remains byte-identical. Local construction uses the owning ModuleDefinition's captured immutable definitions. External construction consults the CURRENT actual published ModuleCodeDescriptor, requires an exported definition, and gives unknown-field failure precedence over required missing value. records:get_definition/2 returns current export options and declaration-order fields, with atom entries for missing defaults and {Field,Default} pairs for explicit defaults; invalid/not-loaded/not-found arguments return badarg. No invented definition registration or always-empty loader is installed.

Access/update use the definition metadata carried by NativeRecordTerm. External field operations require the record's captured exported flag. Local operations require current module/name identity; anonymous field operations allow private values only in their owner module. Empty matching checks identity without requiring exported access. Field matching requires captured fields and permissions. Empty external updates still require accessibility. Existing values continue to be usable after the owner definition is replaced or removed; no physical BEAM pointer, GC, canonicalization or native hot-code equivalence claim is made.

Runtime missing-default reason is novalue, confirmed by pinned atom.names and beam_common.c; the erl_record.c comment spelling no_value is not used as a fabricated atom. v3_core safe_record evaluates the update base before explicit field expressions; record_build_pairs preserves source field expression order. Both are tested. Exact/numeric field equality, term order/ETF/hash/display remain the prior foundation, including its two SDK-derived numeric hash expectations still pending original proof.
