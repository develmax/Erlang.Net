## Actual process_info/2 observations

Existing links, trap_exit, group_leader, registered_name and last_calls remain; dictionary, {dictionary,Key}, messages, message_queue_len, monitors, monitored_by, status, current_function and current_stacktrace now have concrete managed observations. Tuple lookup accepts arbitrary exact term keys, returning undefined if absent. Key lists preserve ordering/duplicates and registered_name legacy singleton behavior. Validation remains before PID liveness lookup, as process_info_bif parses pi_arg2ix before checking PID.

Original pi_args requests owner signal snapshots for dictionary/messages/links/monitor/frame fields. Remote requests use a fresh reference and selective correlated reply, are queued in the target mailbox, and are removed/replied undefined on target death. Suspended receives continue admitting control requests without executing user messages. Queue-length snapshots also use the owner route to avoid an unsafe concurrent managed dictionary/message snapshot. Legacy simple information fields retain their direct safe reads. The actual control entry currently executing is invisible to both mailbox snapshots and queue length; queued user messages, including Nil, are preserved. Control callbacks become visible user messages only when their admission returns a message-priority value.

Monitors derive from the real origin/target monitor table, including repeated references, registered-name reported targets, port kinds and time-offset clock_service. Pending DOWN admissions are flushed before owner snapshots. No connected distribution or native resource monitor rows are invented. Waiting status derives from a real mailbox/hibernate wait and remains waiting while processing control-only requests; suspension uses the actual suspension flag; active code is running. Native host callbacks blocked on arbitrary opaque Task objects are not claimed to have BEAM scheduler status equivalence.

Published logical frames provide cross-flow observation without changing AsyncLocal error-stack capture. current_function self returns the source caller, matching original current_function skipping the heavy process_info BIF; runtime registered builtins are not independently synthesized frames. Stack entries carry real tracked module/function/arity and empty location data, bounded by the existing BacktraceDepth. BEAM program-counter locations, compiler-generated trampoline names, hibernate-specific physical frames, native resource execution and exhaustive stack equivalence remain unfinished. Tail/source function frames use the established compiler execution scopes.
