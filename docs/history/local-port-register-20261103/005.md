## Part 074 — Binary comprehensions and consuming binary generators

Pinned grammar and v3_core binary generator/skip-pattern lowering were inspected; full Core lowering is not ported.

Binary result templates evaluate once per accepted qualifier environment and must yield a bitstring; empty and unaligned chunks append in source order. CLR collects chunks and uses existing BitConstruction once, avoiding repeated copies of the growing output. This changes allocation strategy; allocation-failure timing and BEAM performance are not proven. List and binary generators share private bindings/filter handling, but binary fields consume bits even on mismatch. Successfully decoded fields update fresh bindings/size scope; failed fields retain prior scope; exhaustion is distinct from a consumed mismatch. Relaxed <= skips complete mismatches and ignores incomplete tails. Strict <:= raises {badmatch,RemainingBitstring}, including an incomplete nonempty tail. Invalid sources raise bad_generator. UTF invalid decoding terminates; invalid float encodings consume a field and count as mismatch. Input bytes are copied once per generator, not once per element.

Unsized binary generator fields are statically rejected. Empty generator patterns are explicitly unsupported; zero-progress dynamic patterns raise system_limit to prevent an unbounded loop. These two resource/grammar limitations are local policies, not OTP-equivalence claims or live nonterminating oracle cases. Existing typed string pattern modifiers remain outside scope.
