`erts_send_local_spawn_reply` around13144 retains a token only when both have_seqtrace(token) and child are true. A failure without a child carries NIL. The bad-option/error sender in `bif.c` supplies an ordinary reference and am_undefined rather than creating a child or advancing the token.

The managed asynchronous mode therefore omits the synchronous simulated parent receive and clock update. It emits the actual request and any enabled success send, advances the child even if success is suppressed, and supplies the child reply token to `Mailbox.SendPending`. Mailbox admission, snapshots and unmatched receives cannot update the parent clock; the existing actual matching TraceReceived callback installs the token and merges its serial with the parent's possibly higher clock. A matched ordinary error reply clears the token, retaining the existing clock. Abandonment may discard pending admission without producing a parent receive event.

The request reference is allocated once and is also the monitor reference. Alias identity words may be prepared after the capacity check, but the alias table entry is activated only after successful child allocation. Failed creation retains the ordinary reference and has no alias entry. All updates run under the existing runtime gate, so child death cannot overtake installation of the matching monitor and pending success reply. Group leader, MFA, actual argument list, original options and custom reply tag are preserved by SequenceSpawnDescription.
