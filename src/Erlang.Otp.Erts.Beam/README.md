# Original OTP ERTS modules for .NET

This project/package contains all 22 preloaded/implementation BEAM images from the admitted OTP 29.1.1 Windows x64 release (erts 17.1), original sources, support headers and `erts.app`. SHA256-bound provenance identifies every file and the source commit. The application descriptor lists 19 modules; the remaining three implementation images are recorded explicitly, not omitted or counted as public APIs. This release has no `erts.appup` resource.

Reference `Erlang.Otp.Erts.Beam` as a project or NuGet package. Repository builds reference the runtime composition; package production with `UseInstalledPackage=true` depends on `Erlang.Net.CSharp` 0.1.0. Ordinary C# package consumers set `ErlangPreprocessEnabled=false`. Images and the application resource are embedded and do not require an OTP installation at runtime.

`OtpErts.ReadImage(name)` and `ReadApplication()` verify hashes and return independent bytes. `OtpErts.Beam(name, dependencies)` creates an explicit startup selection; it does not install native bindings or select dependency backends. Original Erlang wrapper bodies execute on our .NET runtime. ERTS BIF/NIF/native primitives remain implemented by the runtime in C#, using its existing explicit bootstrap and canonical native-entry capture rules. Do not publish native stub modules without their required bindings or interpret shipping the images as replacing ERTS with a second native VM.

`erts.app` is retained as upstream metadata. Packaging its preloaded images does not make ERTS an ordinary startable application, certify all native APIs, or supply the complete boot closure. The tests distinguish inspection, actual wrapper/native execution, complete original outcomes, resource cleanup and cold deployment. Existing immutable test fixtures remain separate evidence. The upstream OTP license and source notices are retained; no original ERTS executable is shipped.

The Windows public-consumer example in `tests/Erlang.Otp.Boot.Library.Tests` explicitly registers the existing RuntimeBootstrapAtomics, RuntimeBootstrapFileSystem, RuntimeBootstrapScheduler, RuntimeBootstrapInternalPorts416 and RuntimeBootstrapEtsInspection420 helpers before loading the complete original erts_internal module. Each helper preserves the runtime's own registry/quiescence checks. These bindings are required even when the chosen observation only invokes counters. The example atomically publishes original lists, atomics, counters, erts_internal and selected SASL bodies; its explicit ordinary import selection is not a complete strict startup closure.
