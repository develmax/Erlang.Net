# Original proc_lib formatter observations

This standalone development collector captures the exact combined4 formatter proposal's57 report sources and19 original-only primitive sources against source-built OTP-29.1.1, commit ad05823719d77c8faee87348ea39513d4e2f99c5. It does not load the C# formatter, run .NET, publish a runtime module or add a production BEAM dependency. No expected values are inferred from SDK results.

The copied combined4 manifest is source provenance only; it does not mean its runtime implementation was published or passed validation. The report inputs comprise45 existing text/exception probes and12 raw report probes. Some source wrappers deliberately flatten their returned text; those exact wrappers are retained. The collector itself never flattens or normalizes any result. Every primitive remains original-only until a separate HOST backend comparison is implemented and independently reviewed.

`collect-original.py verify` checks one explicit manifest SHA, the complete tool source closure, the manual workflow bytes, the57/19 track catalog and exact fixture hashes. `collect` additionally requires an exact published checkout SHA, Linux process-group ownership, the pinned clean tracked OTP source, installed29.1.1 version metadata and matching installed runtime/compiler/module identities. The workflow builds original OTP using the same configure/make/install choices as the project's existing differential workflow. It has no .NET setup or SDK execution step.

Each case copies its unmodified bytes to its declared module filename in a fresh private source directory, launches a fresh bounded erlc process with compiler-server use disabled, then launches a fresh bounded original VM. Default printable_range is explicitly latin1, independently of the source's output encoding. Raw argument vectors, selected nonsecret capture environment, stdout, stderr, process status, copied source and fixture BEAM hashes are retained. A timeout terminates only the collector-owned new process group and joins its pipes before continuing.

`returned.etf` contains the exact term returned by run/0, including every nested iolist where the source returns one. An unhandled guest exception instead produces `raised.etf` with its class/reason/stack. `outcome.etf` preserves the corresponding returned/raised envelope. Files are written after the guest try boundary; capture IO errors cannot be mislabeled as guest exceptions. ETF version/size checks do not constitute a semantic decoder or equality assertion. Compile/process/capture failures remain distinct, and all other cases continue. Raw exception terms and identity-bearing output remain unmodified.

`observations.json` reports observations and infrastructure failures, never a formatter compatibility PASS. The captured original outcomes can become independently reviewed test expectations in a later runtime slice. Fixed outputs, guest exception outputs and primitive behavior require separate classification before promotion. A returned observation is not a claim that the proposal matches original OTP.

The published manual workflow accepts the reviewed source-manifest SHA. It checks its actual GITHUB_SHA, verifies source controls, builds pinned original, captures all76 cases and uploads raw evidence even after failure. Root must publish and review this tooling before any workflow dispatch; this source proposal has performed no original or SDK execution.

Source/CLI controls use only the Python standard library and synthetic source/schema inputs. On Linux they also launch actual owned Python child processes to verify raw byte capture, normal exit and bounded process-group timeout with joined pipes. They do not compile Erlang or substitute a fake original runtime. Unique normal workspace scratch directories are retained; Windows TemporaryDirectory ACL precondition failures are preserved separately. Do not run Python with optimization or permit source caches/generated files in this tool's exact closure.
