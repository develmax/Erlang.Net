# Same-VM, same-physical-library NIF environments

This subtool reuses the parent NifUpgradeObservations package's authenticated original provider, process containment, native bridge and host closure. It does not create another OTP installation, bridge42 corpus, runtime build or workflow. Every output is fresh below artifacts/nif-upgrade693. Every script requires --expected-head with the actual reviewed current commit, including a linked working-source snapshot for managed replay; no historical Windows checkout paths or fixed source-count assumptions are admissions.

Sequence (Root/CI is the sole executor):

1. build-native.py: one new genuine nif_env709 DLL/SO using admitted pinned OTP headers/provider; never calls target nif_init. Pass build-inputs.json's explicitly approved SHA, actual provider admission/build receipt and a fresh output directory.
2. collect-original.py: fresh original compilation of two differently checksummed BEAM images of the SAME module and one compiled monitored capture/worker. Reuses the ONE DLL/SO path for successful upgrade and veto in separate fresh original processes. Pass original-inputs.json's approved SHA and the explicitly reviewed real native receipt hash. Full output files are sealed in completion.json.
3. build-driver.py: builds only driver/Env709.csproj against an already built, explicitly reviewed current runtime manifest; it does not build the runtime. Its acquisition receipt is not self-admission: review its actual hash before replay.
4. collect-managed.py: consumes the explicitly approved native/original, runtime/source-freeze and driver receipt hashes; two cases x reviewed/ordinary routes give four complete comparisons. Default is guard-only; --execute is required. Full raw and typed results/stacks, raw event order, old-unload phase, real native owner and runtime cleanup all remain mandatory. Independent route/case failures are collected, then overall failure is returned.

Both native generations use one physical file, unchanged path/hash. allocator_stable/0 compares the actual enif_alloc_env pointer saved during first load with the current callback pointer and returns a BOOLEAN only. No pointer addresses are emitted/normalized and no forced AV is needed for a useful negative control. The actual foreign OS thread uses CreateThread/pthread directly, allocates its own independent env and constructs709 there. The caller copies back/frees only after successful join. No process-bound env is passed across threads. A timed-out join retains possibly-live storage and cannot pass the witness or claim successful cleanup.

Original callbacks/worker remain intact. A real old-image purge occurs only after the monitored worker has returned; old native unload is observed before current-image deletion/purge. All accepted owners must unload. No frame stripping, term projection or event sorting is allowed.

Runtime requirements are production semantics, not a test mode: the VM owns one stable runtime-affine allocator reused across same-VM image tables; alloc_env is moduleless per pinned setup_nif_env(NULL,NULL). Genuine non-process resource callback envs retain their image. Numeric714 must select a real accessible explicit env before a live bound invocation fallback, while retaining stale-invocation rejection, exact runtime separation and NULL/undefined-env immediate behavior. Do not add -nifs to mask this fixture's valid absent-attribute case, or weaken native pointer/runtime admission.

Linux reuses the existing admitted VERSION651_LINUX_BRIDGE_BUILD receipt, whose actual schema has status/pin/head/exports/NativeLoaded=false and library identity; it has no invented Passed field. The bridge is hash-verified and copied into each private host, symlinks/mismatches are refused, and the deployed input is sealed. Ordinary loading uses the runtime's actual namespace callbacks; there is no process-global callback registration.

Limits: this covers one logical VM across code generations. Two logical VMs sharing one physical Windows DLL still need true DLL isolation or authenticated native-thread affinity. It does not establish all TLS/C++ TLS behavior, all N2 partitions, or whole load_nif compatibility. Historical native42/native3 and local accepted receipts remain immutable; publication/CI produces fresh source-bound receipts instead of relabeling them. Full-API and full-contract deltas remain zero for this finite tranche alone.
