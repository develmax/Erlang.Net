# Original term callback observations

Source-only proposal. No original OTP, native compiler, NIF image or SDK comparison has been executed for this fixture. Root must review, publish, compile/admit its own image and dispatch the exact-head original workflow before reporting results.

The single source-bound image covers eleven predicates plus get_list_cell and two array constructors: is_atom(3), is_binary(4), is_ref(5), get_list_cell(13), is_fun(65), is_pid(66), is_port(67), make_tuple_from_array(72), make_list_from_array(73), is_empty_list(74), is_list(82), is_tuple(83), is_number(104), is_map(108). Slots refer to the pinned180-entry Windows table, not Linux symbol indices.

Twenty-two valid term inputs include nil, proper/improper cons, atoms, small/big numbers, tuples, binary/subbinary/bitstring, closure/exported fun, local/external PID/port/ref, map and a conventional Erlang record (which is a tuple). Each row returns both ordinary-env and NULL-env predicate/list-cell calls; only those twelve functions receive NULL, while allocation/construction always use the active environment. External ETF identifiers retain actual values and are asserted remote. Local port is taken from the original VM's existing ports with local identity asserted; no port process is started. Conventional record does not prove the separate managed NativeRecord class. Resource-reference and native-record construction require additional portable fixtures and remain pending.

Each predicate result and get_list_cell return/head/tail is returned as actual ETF. Valid initialized integer term sentinels101/202 must remain unchanged for non-cons, including nil. Cons output pointers are always valid. is_list tests cons-or-nil (including improper list), unlike Erlang is_list/1. Array0 uses NULL only with count0; count3/8193 use an allocated term array, mutate its first element after construction, then free it; Erlang independently compares all returned tuple/list elements in source order. No invalid pointers, zero handles, stale environments or excessive allocations are passed to OTP; managed containment tests are not native equivalence claims.

The thin adapter reuses existing published approval, original runtime build, owned process cleanup, ELF/compiler/header evidence and passive ETF helpers. Capture uses separate bounded compile and observation VMs, records loaded BEAM identities and original runtime metadata, and requires normal receipts plus module deletion/old-code absence. Raw returned values, compile/outcome, images and metadata remain available for later SDK comparison. Term-by-term selected contracts are not full trace equality, complete NIF ABI compatibility or performance proof.
